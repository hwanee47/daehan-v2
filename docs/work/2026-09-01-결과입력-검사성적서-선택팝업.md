## 배경과 목적

결과 입력 화면의 조회조건과 좌측 검사성적서 목록이 실제 입력 양식의 너비를 줄이고 정보 밀도를 높인다. 선택 동작을 팝업으로 분리해 평소에는 검사성적서 입력 양식에 집중하고, 필요할 때만 검색하여 다른 성적서를 불러오게 한다.

## 범위

### 포함

- 결과 입력 본문의 조회조건 영역 제거
- 좌측 검사성적서 목록 제거
- 상단에 현재 선택 정보와 `검사성적서 불러오기` 버튼 배치
- 버튼 클릭 시 검사성적서 검색·선택 팝업 표시
- 통합검색, 초기화, 조회, 검색 결과 목록과 `선택` 동작 제공
- 선택 즉시 팝업을 닫고 해당 검사성적서의 결과 입력 양식 표시
- 선택하지 않은 초기 상태의 안내 화면 제공
- 직접 URL과 작업영역 탭/분할 화면에서 동일하게 동작

### 제외

- 검사성적서 DB 구조 및 조회 권한 변경
- 측정 이력 메뉴와 성적서 관리 화면 변경
- 저장, 인쇄, 최근 이력 기능 변경

## 설계

### UI와 반응형

- 공통: 입력 양식 위에 얇은 선택 바를 두고 선택된 기종·품번/도번·품목상세명을 요약하며 우측에 `검사성적서 불러오기` 버튼을 둔다.
- 팝업: 제목, 한 줄 통합검색, 결과 건수, 스크롤 가능한 결과 목록으로 구성한다. 각 행은 품번/도번과 품목상세명을 우선 표시하고 기종·고객명을 보조 정보로 표시하며 우측에 `선택` 버튼을 둔다.
- 모바일: 팝업을 화면 높이에 맞추고 결과 행의 정보와 버튼을 세로 배치한다.
- 태블릿/데스크톱: 최대 너비 약 960px의 팝업과 가로형 결과 행을 사용한다.
- 빈 상태: 검사성적서를 선택하지 않았으면 중앙 안내와 동일한 불러오기 버튼을 표시한다.
- 로딩/오류: 조회 중 버튼 비활성화, 결과 없음과 서버 오류를 팝업 내부에서 안내한다.
- 접근성: Dialog focus trap과 복귀, Escape 닫기, 검색 Enter 조회, 결과 행 Enter 선택, 명시적인 label과 aria 상태를 유지한다.

### Server/Client 경계

- Server Action: 기존 `searchMeasurementReports`를 재사용해 팝업에서 조회할 때 DB를 재조회한다.
- Client Component: 팝업 열림, 검색어, 결과, 선택 상태와 탭별 미저장 입력 상태를 관리한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 변경 없음
- RLS 정책: 기존 authenticated select 정책 유지
- Storage bucket/path/policy: 변경 없음
- migration과 rollback: 해당 없음. UI 컴포넌트 변경을 되돌리면 복원 가능하다.

## 위험과 승인 사항

- 현재처럼 첫 번째 검사성적서를 자동으로 표시하지 않고, 외부에서 특정 검사성적서를 지정한 경우에만 자동 표시한다. 일반 진입은 선택 전 안내 화면으로 시작한다.
- 검사성적서를 불러오면 이전 화면 임시값은 초기화하며, 최근 이력은 사용자가 명시적으로 선택할 때만 적용한다.
- DB 변경은 없다.

## 결과

- 변경: 상시 조회조건과 목록을 제거하고, 선택 요약 바·빈 상태·검색 가능한 검사성적서 선택 팝업을 추가했다. 일반 진입은 미선택 상태로 시작하고 외부에서 지정된 성적서는 바로 표시한다. 측정 작업 `+` 메뉴는 선택 바의 불러오기 버튼 오른쪽에 배치했다.
- 검증: `npm run lint`, `npx tsc --noEmit`, `npx next build --webpack` 통과.
- 미실행: 로컬 브라우저가 로그인 화면으로 이동해 로그인 후의 직접 URL·탭·분할 화면과 viewport별 수동 검증은 수행하지 못했다.
- 남은 위험/후속 작업: 로그인된 환경에서 Dialog focus 복귀와 좁은 분할 패널의 팝업 결과 행을 확인해야 한다.
