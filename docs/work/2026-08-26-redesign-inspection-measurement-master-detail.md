## 배경과 목적

측정할 검사성적서를 select로 고르는 현재 흐름을 왼쪽 성적서 목록과 오른쪽 결과 입력 영역으로 분리해 선택 대상을 빠르게 전환하고, 결과 입력 영역에는 가능한 최대 너비를 제공한다.

## 범위

### 포함

- 측정결과 입력 화면을 좌측 성적서 목록·우측 결과 입력 구조로 변경
- 선택된 성적서의 단일 강조 및 키보드 선택
- 우측 성적서 양식이 980px에 고정되지 않고 가용 너비까지 확장되도록 변경
- 좁은 작업 패널에서 목록과 입력 영역의 반응형 전환
- 좌우 영역의 독립적인 overflow 처리

### 제외

- 검사성적서 데이터, 저장 Action 및 DB 변경
- 측정 양식의 필드·업무 규칙 변경
- 목록 검색·필터·페이지네이션 추가

## 완료 조건

- [x] 넓은 작업영역에서 왼쪽에 성적서 목록, 오른쪽에 결과 입력 화면이 표시된다.
- [x] 오른쪽은 목록보다 훨씬 넓고 남은 가용 너비를 모두 사용한다.
- [x] 목록 행을 클릭하거나 키보드로 선택하면 오른쪽 입력 내용이 교체된다.
- [x] 성적서별 입력 중인 지역 상태가 화면 전환 시 유지된다.
- [x] 좁은 패널에서는 목록이 위, 입력 화면이 아래로 배치되고 입력 표는 자체 가로 스크롤된다.
- [x] 선택, 빈 상태, 오류 및 저장 메시지가 명확하게 표시된다.

## 현재 구현 조사

- 관련 route/component: `inspection-measurements/page.tsx`, `inspection-measurement-sheet.tsx`
- 관련 Supabase table/bucket: 기존 검사성적서 조회 결과만 사용하며 변경 없음
- 재사용할 기존 패턴: 성적서 관리 화면의 좌측 목록·우측 상세 패턴, workspace container query
- 문서와 구현의 차이: 현재 결과 양식은 `w-[980px]` 고정 너비이고 상단 select로 성적서를 선택한다.

## 설계

### UI와 반응형

- 모바일: 성적서 목록을 위쪽의 제한 높이 영역으로 배치하고 결과 입력을 아래에 표시한다. 결과 양식은 최소 업무 너비를 유지하며 내부 가로 스크롤한다.
- 태블릿: 작업 패널 너비가 충분하지 않으면 동일한 상하 배치를 유지한다.
- 데스크톱: `280~300px + minmax(0, 1fr)` 비율로 좌우 배치해 우측이 남은 폭을 모두 사용한다.
- 로딩/빈 상태/오류/권한: 기존 서버 로딩과 오류 처리를 유지하고 목록이 없거나 선택되지 않은 경우 우측 빈 상태를 표시한다.
- 접근성: 목록 항목은 `aria-selected`, focus 표시, Enter·Space 선택을 지원한다.

### Server/Client 경계

- Server Component/Action: 변경 없음
- Client Component/Zustand: 현재 컴포넌트의 지역 상태를 유지하며 별도 전역 상태를 추가하지 않는다.

### 데이터와 Supabase

- schema 변경: 해당 없음
- PK/FK/index: 해당 없음
- RLS 정책: 해당 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음. 레이아웃 컴포넌트 변경만 되돌리면 된다.

## 변경 계획

1. 상단 성적서 select를 제거하고 컴팩트한 좌측 목록을 추가한다.
2. workspace container 기준으로 상하·좌우 배치를 전환한다.
3. 결과 양식을 `w-full min-w-[980px]`로 바꿔 우측 가용 너비를 최대한 사용한다.
4. 목록과 입력 영역의 overflow, 선택 상태 및 키보드 흐름을 검증한다.

## 위험과 승인 사항

- 2분할의 좁은 패널에서는 980px 측정표를 축소하지 않고 가로 스크롤로 유지한다. 숫자 입력칸 가독성을 보존하기 위한 선택이다.
- DB와 저장 규칙은 변경하지 않는다.
