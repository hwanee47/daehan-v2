## 배경과 목적

결과 입력 저장 시 검사자와 검사일자를 필수로 요구하지 않고 빈 값 저장을 허용한다.

## 범위

### 포함

- 검사자와 검사일자의 화면 필수 속성을 제거한다.
- 서버에서 빈 값을 허용하고 값이 있을 때만 길이·날짜 유효성을 검사한다.
- DB 저장 함수에서 두 필드의 필수 조건을 제거하고 빈 값을 `null`로 저장한다.

### 제외

- 입력란 및 기존 기본값 제거
- 다른 필드의 필수 조건 변경
- 기존 데이터 변환

## 완료 조건

- [x] 검사자와 검사일자를 비운 상태로 저장할 수 있다.
- [x] 입력된 검사자는 100자 이하이고 입력된 검사일자는 유효한 `YYYY-MM-DD`여야 한다.
- [x] 빈 값은 현재 성적서와 측정이력에 `null`로 저장된다.

## 현재 구현 조사

- 관련 route/component: `inspection-measurements/inspection-measurement-sheet.tsx`, `inspection-reports/actions.ts`
- 관련 Supabase table/bucket: `inspection_reports`, `inspection_measurement_runs`, `save_inspection_measurement_entry`
- 재사용할 기존 패턴: optional text/date의 빈 문자열을 `null`로 변환
- 문서와 구현의 차이: 테이블 컬럼은 nullable이지만 화면·서버·DB 함수가 두 값을 필수로 검사한다.

## 설계

### UI와 반응형

- 모든 화면 크기에서 기존 입력 배치를 유지하고 `required`만 제거한다.
- 접근성: 기존 label과 캘린더 키보드 동작 유지

### Server/Client 경계

- Server Action: 값이 있을 때만 검사하고 빈 검사일자는 RPC에 `null`로 전달한다.
- Client Component: 필수 속성을 제거하며 지역 상태와 기본값은 유지한다.

### 데이터와 Supabase

- schema 변경: 기존 함수의 검증·저장 로직만 교체하며 컬럼 타입은 변경하지 않는다.
- PK/FK/index/RLS/Storage: 변경 없음
- migration과 rollback: 이전 함수 정의로 교체하면 복원된다.
