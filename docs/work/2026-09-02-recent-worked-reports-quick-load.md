## 배경과 목적

결과입력 최초 진입 시 매번 검사성적서 검색 팝업을 열어야 하는 불편을 줄인다. 최근 측정 작업이 있었던 검사성적서 5개를 바로 보여주고 한 번의 선택으로 신규 결과입력을 시작할 수 있게 한다.

## 범위

### 포함

- 결과입력에 `최근 작업 성적서` Top 5 영역 추가
- 최근 저장·인쇄 활동 시각 기준으로 검사성적서를 중복 제거하여 최신순 표시
- 항목 선택 시 검사성적서 원본 구조만 불러오고 측정값은 빈칸으로 시작
- 기존 `검사성적서 불러오기` 검색 기능 유지
- 로딩, 빈 상태와 조회 오류 처리

### 제외

- 최근 측정이력의 결과값 자동 복원
- 검사성적서 또는 측정이력 데이터 변경
- DB 테이블, 함수, 인덱스와 RLS 변경
- 사용자별 즐겨찾기·고정 기능

## 완료 조건

- [x] 최초 진입 시 최근 작업한 서로 다른 검사성적서를 최대 5개 표시한다.
- [x] 각 항목은 `기종 · 상세품명 (도번)` 형식이며 기종은 primary blue로 표시한다.
- [x] 항목을 선택하면 해당 검사성적서를 불러오되 측정결과는 빈칸이다.
- [x] 최근 작업이 없어도 기존 검색 버튼으로 검사성적서를 불러올 수 있다.
- [x] 최근 작업 조회 실패가 전체 결과입력 기능을 막지 않는다.

## 현재 구현 조사

- 관련 route/component: `inspection-measurements/page.tsx`, `inspection-measurement-sheet.tsx`, `inspection-measurements/actions.ts`, `workspace-data-actions.ts`

- 재사용할 기존 패턴: `selectReport`의 신규 결과입력 초기화, 검사성적서 검색 결과 표시 형식
- 문서와 구현의 차이: 해당 없음

## 설계

### UI와 반응형

- 성적서가 선택되지 않은 최초 화면에 평면 목록 형태의 `최근 작업 성적서` 영역을 표시한다.
- 각 행은 기종, 상세품명·도번, 최근 작업 일시와 `불러오기` 행동을 제공한다.
- 모바일은 세로 목록, 넓은 workspace에서는 가독성을 유지하는 1열 compact list를 사용한다.
- 목록 아래에 `다른 검사성적서 검색` 버튼을 유지한다.

### Server/Client 경계

- Server Action에서 활성 측정이력을 최신순으로 조회하고 검사성적서별 최신 활동만 남겨 최대 5개를 반환한다.
- Client Component는 조회 결과를 표시하고 기존 `selectReport`를 호출한다.
- 이력의 측정값이나 회차 상세는 조회하지 않는다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 기존 `inspection_measurement_runs` 최신 조회 인덱스 사용
- RLS 정책: 기존 authenticated select 정책 사용
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음

## 변경 계획

1. 최근 작업 성적서 조회 타입과 Server Action을 추가한다.
2. 결과입력 최초 빈 화면에 Top 5 빠른 선택 UI를 추가한다.
3. 선택 시 기존 신규 결과입력 초기화 흐름을 재사용한다.
4. 직접 URL과 탭 작업영역에서 로딩·빈 상태·오류를 검증한다.

## 위험과 승인 사항

- `최근 작업`은 저장 또는 인쇄로 생성된 활성 측정이력의 최신 시각을 기준으로 한다.
- Top 5 선정에만 이력 헤더를 사용하며 과거 측정결과는 불러오지 않는다.
- Standard 기능 변경으로 구현 전 사용자 승인이 필요하다.
