## 배경과 목적

현재 업무 탭은 Next.js URL을 전환하는 내비게이션 탭이라 이전 page 컴포넌트가 교체되고, 저장하지 않은 입력값·선택 행·AG Grid 상태가 초기화될 수 있다. 열린 업무 화면을 탭별로 한 번만 생성하고 탭을 닫기 전까지 동시에 마운트해, 열린 탭 수와 관계없이 작업 상태를 유지한다.

## 범위

### 포함

- 검사성적서, 품목관리, 오차범위관리, 코드관리 화면을 공통 클라이언트 작업영역의 독립 패널로 전환
- 메뉴 클릭 시 작업영역 안에 해당 패널을 지연 생성하고 활성 탭만 표시
- 비활성 탭은 언마운트하지 않고 숨겨 React state, DOM 입력값, 선택 행, AG Grid 필터·정렬·스크롤 상태 유지
- 탭 전환 시 페이지 URL 이동 없이 활성 탭 상태만 변경
- 모든 열린 탭을 수량 제한 없이 유지
- 탭 닫기 시에만 해당 패널과 작업 상태 제거
- 새로고침 후 열린 탭 목록과 마지막 활성 탭 복원
- 기존 Server Action과 RLS 권한 경계 유지
- 로그아웃 또는 인증 사용자 변경 시 열린 탭과 메모리 작업 상태 제거
- 모바일 가로 스크롤 탭과 접근 가능한 탭/탭패널 관계 제공

### 제외

- 새로고침·브라우저 종료 후 저장하지 않은 입력값과 팝업 내부 초안 복원
- 여러 브라우저나 기기 사이 작업 상태 동기화
- DB schema, RLS, Storage 또는 인증 방식 변경
- 탭 순서 드래그, 탭 복제, 우클릭 메뉴
- 닫기 전 저장하지 않은 변경 경고 체계의 전면 도입

## 완료 조건

- [x] 메뉴를 선택해도 업무 route로 페이지 이동하지 않고 작업영역에서 탭이 열린다.
- [x] 열린 모든 탭의 패널이 탭을 닫기 전까지 마운트 상태를 유지한다.
- [x] 네 개 업무 탭을 모두 열어 유지할 수 있는 패널 구조를 적용했다.
- [x] 탭을 닫으면 해당 패널 상태만 제거되고 인접 탭이 활성화된다.
- [x] 새로고침 후 탭 목록과 활성 탭이 복원되며 각 화면 데이터는 다시 안전하게 로드된다.
- [x] 비로그인·비관리자 권한과 기존 RLS가 우회되지 않는다.
- [x] 가로 스크롤과 키보드 탭 전환 구조를 적용했다.

## 현재 구현 조사

- 관련 route/component: `src/app/(app)/layout.tsx`, `src/components/layout/app-header.tsx`, `src/components/layout/app-tabs.tsx`, `src/app/reference-information-menu.tsx`, 네 업무 route의 `page.tsx`와 클라이언트 관리 컴포넌트
- 관련 Supabase table/bucket: 읽기 대상은 기존 `users`, `items`, `item_details`, `item_tolerance_ranges`, `code_groups`, `code_details`; schema 변경 없음
- 재사용할 기존 패턴: 기존 Server Action, 관리 화면 클라이언트 컴포넌트, Zustand persist, AG Grid 설정, Supabase 서버 클라이언트와 RLS
- 문서와 구현의 차이: 현재 아키텍처 문서는 Server page가 기능 컴포넌트에 데이터를 공급하는 route 중심 구조다. 제안 작업은 여러 업무 패널의 수명과 활성 상태를 공통 작업영역이 소유하도록 경계를 변경한다.

## 설계

### UI와 반응형

- 모바일: 탭 목록은 한 줄 가로 스크롤로 제공하고 활성 패널 하나만 화면에 표시한다.
- 태블릿: 동일한 작업영역을 사용하며 탭의 최소 너비와 터치 영역을 유지한다.
- 데스크톱: 열린 순서대로 탭을 표시하고 활성 패널 하나만 보이되 나머지는 DOM에 숨겨둔다.
- 로딩/빈 상태/오류/권한: 각 패널이 독립적으로 최초 로딩, 빈 상태와 오류를 표시한다. 권한 실패 시 패널을 만들지 않고 안전한 화면으로 복귀한다.
- 접근성: `tablist`, `tab`, `tabpanel`, `aria-selected`, `aria-controls`를 연결하고 방향키·Home·End·Delete 키보드 동작을 제공한다.

### Server/Client 경계

- Server Component/Action: 공통 작업영역 진입 시 인증과 역할을 서버에서 검증한다. 각 패널의 초기 데이터는 서버 전용 loader 경계에서 조회하고 기존 변경 Server Action을 재사용한다.
- Client Component/Zustand: 작업영역 shell이 열린 탭, 활성 탭과 패널 수명을 관리한다. 패널의 임시 입력·선택·그리드 상태는 해당 패널의 지역 상태로 유지하며 전역 store에 복제하지 않는다.
- 패널 로딩: 탭을 처음 열 때만 허용된 서버 loader를 호출해 초기 데이터를 가져오고 패널을 생성한다. 이후 탭 전환은 서버 요청이나 route 이동 없이 표시만 전환한다.
- 저장 후 동기화: 기존 Server Action 성공 시 해당 패널 데이터만 갱신하며 다른 열린 패널을 언마운트하지 않는다. 같은 테이블을 보는 패널 간 최신성 규칙을 명시적으로 처리한다.

### 데이터와 Supabase

- schema 변경: 해당 없음
- PK/FK/index: 해당 없음
- RLS 정책: 기존 정책 유지. 클라이언트의 탭 노출 여부를 권한 경계로 사용하지 않는다.
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음. 작업영역 shell을 제거하고 기존 route 링크와 page 구성을 복원하면 rollback할 수 있다.

## 변경 계획

1. 탭 대상별 서버 데이터 loader와 권한 결과 계약을 정의한다.
2. 기존 page의 화면 본문을 작업영역에서 재사용 가능한 패널 단위로 분리한다.
3. 열린 탭과 활성 탭을 관리하는 Zustand 상태를 버전이 있는 persist 구조로 확장한다.
4. 패널을 최초 접근 시 생성하고 닫기 전까지 유지하는 작업영역 shell을 구현한다.
5. 헤더·기준정보 메뉴가 route 이동 대신 작업영역 탭 열기 동작을 사용하도록 연결한다.
6. 기존 공개 업무 URL은 직접 접근·새로고침 호환을 유지하고 대응 탭을 활성화하도록 연결한다.
7. 탭 간 동일 데이터 변경 시 필요한 최소 패널 갱신 규칙과 로그아웃 초기화를 구현한다.
8. 정적 검사, 빌드, 네 탭 동시 상태 유지, 반응형과 키보드 동작을 검증한다.
9. 합의된 공통 작업영역 경계를 `docs/architecture.md`에 반영한다.

## 위험과 승인 사항

- 네 업무 화면과 AG Grid가 동시에 메모리에 남으므로 열린 탭 수에 비례해 브라우저 메모리 사용량이 증가한다.
- 화면을 숨겨도 각 패널의 effect나 구독이 자동 중지되지 않는다. 비활성 패널의 불필요한 polling·focus 동작이 없는지 점검해야 한다.
- 품목관리와 오차범위관리처럼 같은 데이터를 보는 탭은 한쪽 저장 후 다른 탭 데이터가 오래된 상태일 수 있어 선택적 재조회 규칙이 필요하다.
- 이 제안에서 “상태 유지”는 탭 전환과 클라이언트 내비게이션 동안을 의미한다. 새로고침 후에는 탭 목록만 복원하고 저장하지 않은 폼 초안은 복원하지 않는다.
- 공통 렌더링·데이터 로딩 경계를 바꾸는 Architecture 작업이므로 이 제안에 대한 별도 명시적 승인이 필요하다.

## 결과

- 변경: 메뉴를 route 링크에서 작업영역 열기 버튼으로 바꾸고, 열린 패널을 닫기 전까지 동시에 마운트하는 shell을 추가했다. 네 업무 패널의 초기 데이터는 서버 layout에서 권한에 따라 준비하며, 검색은 패널 지역 상태로 처리한다. Zustand persist v2와 이전 저장 형식 migration, 활성/닫기/숨기기 상태를 추가했다. 기존 업무 URL 직접 접근과 Server Action/RLS는 유지했다.
- 검증: `npm run lint`, `npx tsc --noEmit`, `npx next build --webpack`, `git diff --check`를 통과했고 개발 서버 홈 요청의 200 응답을 확인했다.
- 미실행: 별도 테스트 환경과 브라우저 인증 세션이 없어 실제 관리자 계정으로 네 탭을 열어 입력·AG Grid 상태를 반복 전환하는 검증, 360px/768px/1280px 시각 검증과 권한별 브라우저 검증은 실행하지 못했다.
- 남은 위험/후속 작업: 관리자 layout 진입 시 네 업무 패널의 초기 데이터를 한 번에 조회하므로 데이터 증가에 따라 초기 요청 비용을 모니터링해야 한다. 저장 후 layout 데이터를 재조회하지만 패널 지역 UI 상태는 같은 컴포넌트 위치에서 유지된다. 새로고침 후 저장하지 않은 폼 초안은 복원하지 않는다.
