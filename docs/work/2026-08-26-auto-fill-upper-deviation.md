# 하한 편차 입력 시 상한 편차 자동 입력

## 배경과 목적

오차범위 추가·수정 시 대칭 공차를 입력하려면 하한과 상한 편차를 각각 입력해야 한다. 하한 편차를 기준으로 상한 편차를 자동 채워 반복 입력을 줄이되, 비대칭 공차도 계속 입력할 수 있게 한다.

## 범위

### 포함

- 하한 편차 입력값의 절댓값을 상한 편차에 자동 반영
- 예: 하한 `-0.05` → 상한 `0.05`, 하한 `0` → 상한 `0`, 하한 `0.05` → 상한 `0.05`
- 상한 편차는 자동 입력 후에도 사용자가 직접 수정 가능
- 하한 편차가 다시 변경되면 변경된 값 기준으로 상한 편차를 다시 자동 반영
- 추가·수정 Dialog 모두 동일하게 적용
- 자동 입력 동작을 입력 안내 문구에 명시

### 제외

- Server Action의 편차 검증 규칙 변경
- 기존 저장 데이터 자동 변환
- DB schema, RLS와 Supabase 변경
- 목록 표시 형식 변경

## 설계

### UI와 반응형

- 모바일: 현재 1열 입력 배치와 필드 순서를 유지한다.
- 태블릿: 현재 2열 입력 배치를 유지한다.
- 데스크톱: 현재 Dialog 크기와 2열 배치를 유지한다.
- 로딩/빈 상태/오류/권한: 별도 로딩은 없고 기존 오류·권한 처리를 유지한다. 하한을 비우면 상한도 빈 값으로 동기화한다.
- 접근성: 기존 label, number input, 키보드 입력과 오류 연결을 유지하고 자동 입력 규칙을 설명 문구로 제공한다.

### 데이터와 Supabase

## 변경 계획

1. `NumberField`가 제어 값과 변경 이벤트를 선택적으로 받을 수 있게 확장한다.
2. `RangeEditor`에 하한·상한 편차 문자열 지역 상태를 추가한다.
3. 하한 입력 시 절댓값을 계산해 상한을 자동 반영하고, 빈 값과 입력 중 상태를 안전하게 처리한다.
4. 상한 직접 수정을 허용하고 안내 문구를 갱신한다.
5. 추가·수정 초기값, 음수·0·양수·소수 입력과 서버 검증을 확인한다.
6. lint, TypeScript와 프로덕션 빌드를 실행한다.

## 위험과 승인 사항

- 제안하는 자동 입력 규칙은 단순 복사가 아니라 대칭 공차 기준의 `상한 편차 = |하한 편차|`다.
- 하한을 변경할 때마다 상한에 자동값을 다시 적용하므로, 비대칭 상한값은 하한 입력을 마친 뒤 수정해야 한다.
- DB와 서버 검증 규칙은 변경하지 않는다.
