## 배경과 목적

현재 헤더 메뉴를 선택하면 해당 URL로 바로 이동한다. 업무 화면을 여러 개 오갈 때 열린 화면을 다시 찾기 쉽도록, 기존 App Router URL 이동을 유지하면서 헤더 아래에 열린 메뉴 탭을 제공한다.

## 범위

### 포함

- `(app)` 공통 레이아웃에 라우트 연동 탭 바 추가
- 검사성적서, 품목관리, 오차범위관리, 코드관리 메뉴를 탭 대상으로 등록
- 메뉴 선택 시 중복 없이 탭을 열고 해당 URL로 이동
- 탭 선택, 개별 닫기와 현재 탭 표시
- 활성 탭을 닫으면 직전에 열려 있는 인접 탭으로 이동
- 새로고침 후 열린 탭 목록 복원
- 모바일 가로 스크롤과 데스크톱 탭 배치
- 키보드 포커스와 탭 닫기 접근성 이름 제공

### 제외

- 여러 페이지 컴포넌트를 동시에 마운트하는 MDI 방식
- 각 페이지의 입력값, 스크롤, AG Grid 필터·선택 상태 보존
- 홈과 프로필 화면을 업무 탭으로 관리
- DB, Supabase, 인증 또는 공개 URL 변경
- 탭 순서 드래그, 전체 닫기, 우클릭 메뉴

## 현재 구현 조사

- 관련 route/component: `src/app/(app)/layout.tsx`, `src/components/layout/app-header.tsx`, `src/app/reference-information-menu.tsx`
- 관련 Supabase table/bucket: 해당 없음. 헤더의 기존 사용자·역할 조회는 변경하지 않는다.
- 재사용할 기존 패턴: Next.js `Link`, `usePathname`, `useRouter`, `src/stores/ui-store.ts`의 Zustand 전역 UI 상태, shadcn semantic token
- 문서와 구현의 차이: 확인된 차이 없음

## 설계

### UI와 반응형

- 모바일: 헤더 아래 한 줄 탭 바를 가로 스크롤로 제공하고 탭이 줄바꿈되지 않게 한다.
- 태블릿: 동일한 탭 바를 사용하며 사용 가능한 너비 안에서 가로 스크롤한다.
- 데스크톱: 헤더 아래 전체 너비 탭 바에 열린 순서대로 표시한다.
- 로딩/빈 상태/오류/권한: 열린 탭이 없으면 탭 바를 숨긴다. 페이지 자체의 기존 상태와 권한 처리는 유지한다.
- 접근성: 현재 탭에 `aria-current="page"`를 제공하고 닫기 버튼에 화면명이 포함된 접근성 이름과 포커스 스타일을 제공한다.

### Server/Client 경계

- Server Component/Action: `(app)` layout과 각 page의 서버 렌더링 및 Supabase 조회는 유지한다.
- Client Component/Zustand: 작은 클라이언트 탭 바가 현재 pathname을 관찰하고, 열린 탭 목록과 닫기 동작을 관리한다. 저장 데이터에는 경로와 표시 이름만 포함한다.

### 데이터와 Supabase

- schema 변경: 해당 없음
- PK/FK/index: 해당 없음
- RLS 정책: 해당 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음. 탭 컴포넌트와 상태 변경을 되돌리면 기존 페이지 이동 방식으로 복구된다.

## 변경 계획

1. Next.js 16의 Link, pathname과 클라이언트 내비게이션 관련 로컬 가이드를 확인한다.
2. 탭 대상 route와 표시 이름을 공통 설정으로 정의한다.
3. Zustand UI store에 열린 탭 목록과 복원 가능한 persist 상태를 추가한다.
4. pathname과 열린 탭을 연결하는 접근 가능한 공통 탭 바를 구현한다.
5. `(app)` layout에 탭 바를 배치하고 기존 메뉴 링크와 연결 동작을 확인한다.
6. 정적 검사와 반응형·키보드 동작을 검증한다.

## 위험과 승인 사항

- 새로고침 복원을 위해 브라우저 저장소에 메뉴 경로와 표시 이름을 저장한다. 사용자 데이터나 인증 정보는 저장하지 않는다.
- 탭 전환은 기존 라우트 이동이므로 저장하지 않은 폼 입력, 스크롤과 AG Grid 내부 상태는 유지되지 않는다.
- 공통 레이아웃과 여러 화면이 공유하는 클라이언트 UI 상태를 변경하므로 이 제안에 대한 명시적 승인이 필요하다.
