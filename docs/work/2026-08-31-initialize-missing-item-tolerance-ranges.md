# 신규 품목 오차범위 초기값 적용

## 상태

- 단계: 완료
- 담당: Codex
- 작성일: 2026-08-31
- 승인 상태: 승인
- 승인 응답/일시: 사용자 `승인` / 2026-08-31

## 배경과 목적

기존 일괄 복제 이후 추가된 품목 중 오차범위가 전혀 없는 품목에 `B302B-12200`의 오차범위를 초기값으로 적용한다.

## 범위

### 포함

- 기준 품목과 기준 오차범위 존재 여부 검증
- 오차범위가 한 건도 없는 현재 품목에만 기준 오차범위 복제
- 적용 행 수와 품목별 범위 집합의 동일성 검증
- 원격 dry run, 적용 및 사후 migration 상태 검증

### 제외

- 기존 오차범위가 한 건이라도 있는 품목의 변경
- 테이블, 컬럼, 제약, 인덱스와 RLS 변경
- 향후 생성될 품목에 대한 자동 초기화 기능
- 애플리케이션 UI와 코드 변경

## 완료 조건

- [x] 적용 시점에 오차범위가 없던 모든 품목이 기준 품목과 동일한 범위 집합을 가진다.
- [x] 기존 오차범위는 수정하거나 삭제하지 않는다.
- [x] 기준 품목이나 기준 범위가 없으면 전체 작업이 중단된다.
- [x] 대상 품목이 없으면 변경 없이 정상 종료한다.

## 현재 구현 조사

- 관련 route/component: `master/tolerance-ranges`
- 관련 Supabase table/bucket: `items`, `item_tolerance_ranges`
- 재사용할 기존 패턴: `20260831000000_copy_b302b_12200_tolerance_ranges.sql`
- 문서와 구현의 차이: 기존 migration은 최초 적용 시 모든 대상이 비어 있어야 하지만, 이번에는 범위가 전혀 없는 품목만 선별해야 한다.

## 설계

### UI와 반응형

- 해당 없음: 데이터 일괄 적용 작업이다.

### Server/Client 경계

- 해당 없음: 애플리케이션 코드를 변경하지 않는다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 기존 제약 유지
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 적용 대상의 `seq`를 transaction 안에서 고정한 뒤 기준 범위를 복제한다. 실패 시 전체 transaction이 rollback된다. 적용 후 되돌려야 하면 이번 적용 대상에 생성된 범위만 삭제하는 보정 migration을 사용한다.

## 변경 계획

1. 오차범위가 없는 대상 품목을 고정하고 기준 범위를 복제하는 migration을 작성한다.
2. migration 내부에서 삽입 행 수와 범위 집합을 검증한다.
3. 원격 dry run 후 migration을 적용한다.
4. 원격 migration 목록과 후속 dry run을 확인한다.

## 위험과 승인 사항

- 현재 등록된 품목만 대상이며 이후 생성되는 품목은 자동 적용되지 않는다.
- 범위가 일부라도 존재하는 품목은 사용자 정의 데이터 보호를 위해 제외한다.

## 결과

- 변경: 오차범위가 전혀 없는 현재 품목에 `B302B-12200`의 오차범위를 복제하는 migration을 원격 적용했다.
- 검증: 적용 전 dry run에서 이번 migration 한 개만 대상으로 확인했다. migration 내부에서 예상 삽입 행 수와 대상별 양방향 집합 차이를 검사했고, 적용 후 local/remote migration 일치와 후속 dry run `upToDate: true`를 확인했다.
- 미실행: UI와 애플리케이션 코드는 변경하지 않아 lint, TypeScript와 화면 검증은 해당 없음이다.
- 남은 위험/후속 작업: 향후 신규 품목 자동 초기화 또는 관리 화면의 일괄 적용 기능은 별도 작업이다.
