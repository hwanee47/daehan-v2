## 배경과 목적

성적서 관리에서 선택한 성적서의 측정값을 입력하려면 사용자가 별도로 결과 입력 메뉴를 열고 같은 성적서를 다시 찾아야 한다. 상세 영역에 `결과 입력` 행동을 제공하고, 클릭한 성적서가 선택된 기존 결과 입력 화면을 바로 열어 중복 탐색을 줄인다.

## 범위

### 포함

- 성적서 관리의 선택 성적서 행동 영역에 `결과 입력` 버튼 추가
- 버튼 클릭 시 기존 `/inspection-measurements` 작업 탭을 열거나 이미 열린 탭을 활성화
- 결과 입력 화면에서 전달받은 성적서를 즉시 선택하고 빈 측정값 입력 상태 표시
- 탭 최대 5개 제한과 기존 탭 마운트 유지 정책 준수
- 키보드 접근성과 작은 작업 패널에서의 버튼 배치 확인

### 제외

- 신규 결과 입력 화면 또는 URL 추가
- 측정결과 자동 저장이나 최근 이력 자동 불러오기
- 검사성적서, 측정결과 및 이력 DB 구조 변경
- 기존 검색·저장·인쇄 동작 변경

## 완료 조건

- [x] 클릭하면 결과 입력 탭이 열리거나 활성화되고 선택한 성적서가 표시된다.
- [x] 결과 입력 탭이 이미 열려 있어도 대상 성적서가 변경된다.

## 설계

### UI와 반응형

- 모바일: 상세 헤더 행동 버튼이 줄바꿈 가능하도록 유지한다.
- 태블릿: 수정·삭제와 동일한 크기의 `결과 입력` 버튼을 제공한다.
- 데스크톱: 상세 헤더 우측 첫 번째 주요 행동으로 배치한다.
- 로딩/빈 상태/오류/권한: 성적서 미선택 시 버튼을 표시하지 않는다. 결과 입력 데이터 로딩 중에는 기존 로딩 UI를 사용한다.
- 접근성: 버튼 이름을 텍스트로 제공하고 키보드 클릭을 지원한다.

### Server/Client 경계

- Server Component/Action: 변경 없음
- Client Component/Zustand: 선택한 성적서 번호를 일회성 작업영역 이동 의도로 전달하고, 결과 입력 패널에서 이를 반영한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 해당 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음. UI와 클라이언트 상태 변경을 되돌리면 된다.

## 변경 계획

1. 작업영역 UI store에 선택 성적서를 결과 입력 탭으로 여는 명시적 동작을 추가한다.
2. 성적서 관리 상세 헤더에 `결과 입력` 버튼을 추가한다.
3. 결과 입력 패널이 전달된 성적서 번호를 받아 기존 목록에서 선택하도록 연결한다.
4. 기존 빈 측정값 초기화 규칙과 탭 한도 동작을 검증한다.

## 위험과 승인 사항

- 결과 입력 탭은 기존처럼 하나만 유지한다. 다른 성적서의 미저장 입력값이 있는 상태에서 새 성적서로 이동하면 기존 화면의 성적서별 지역 상태는 유지되지만 활성 성적서가 바뀐다.
- DB 변경과 외부 시스템 변경은 없다.
- 이 문서 승인 전에는 애플리케이션 코드를 수정하지 않는다.
