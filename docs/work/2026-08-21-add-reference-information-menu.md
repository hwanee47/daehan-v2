## 배경과 목적

메인 헤더의 주요 메뉴에 기준정보 영역을 추가하고, 사용자가 요청한 세 가지 하위 메뉴를 확인할 수 있게 한다.

## 범위

### 포함

- 메인 헤더에 `기준정보` 상위 메뉴를 추가한다.
- 하위 메뉴로 `품목관리`, `오차범위관리`, `코드관리`만 추가한다.
- 키보드와 모바일에서도 하위 메뉴를 열고 닫을 수 있게 한다.

### 제외

- 품목관리, 오차범위관리, 코드관리 페이지 생성
- 데이터베이스, Supabase, 권한 정책 변경
- 검사성적서 메뉴 및 기존 화면 변경
- 요청하지 않은 추가 메뉴나 기능

- 관련 route/component: `src/app/page.tsx`의 메인 헤더 내 `주요 메뉴` 내비게이션
- 관련 Supabase table/bucket: 해당 없음 — 메뉴 표시만 변경한다.
- 재사용할 기존 패턴: 기존 헤더의 44px 이상 링크 영역, semantic color와 rounded-xl 스타일
- 문서와 구현의 차이: 현재 주요 메뉴에는 `검사성적서` 링크만 있고 드롭다운 primitive와 세 하위 route는 없다.

## 설계

### UI와 반응형

- 모바일: 기준정보 버튼 아래에 화면 폭을 넘지 않는 메뉴를 표시한다.
- 태블릿: 데스크톱과 같은 하위 메뉴 구성을 사용한다.
- 데스크톱: 기준정보 버튼을 누르면 세 항목이 세로로 표시된다.
- 로딩/빈 상태/오류/권한: 데이터 요청이 없어 해당 없음. 미구현 페이지 항목은 비활성 상태로 표시한다.
- 접근성: 실제 버튼, `aria-expanded`, `aria-haspopup`을 사용하고 키보드 포커스를 유지한다.

### Server/Client 경계

- Server Component/Action: 홈 페이지의 사용자 정보 조회와 기존 렌더링은 유지한다.
- Client Component/Zustand: 드롭다운의 열림 상태만 담당하는 작은 Client Component를 사용한다. Zustand는 사용하지 않는다.

### 데이터와 Supabase

- schema 변경: 해당 없음
- PK/FK/index: 해당 없음
- RLS 정책: 해당 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음
