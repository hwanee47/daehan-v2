## 배경과 목적

결과 입력에서 신규 행에 측정값만 입력할 때 기준치수와 공차의 필수 검증으로 저장이 차단된다. 신규 검사항목의 기준치수와 공차를 선택 입력으로 바꾸고 측정값과 이력을 정상 저장한다.

## 범위

### 포함

- 현재 검사항목과 측정이력 항목의 기준치수·공차 nullable 변경
- 결과 입력 저장 함수의 빈 문자열→NULL 변환
- 값이 있는 공차의 숫자 및 하한·상한 검증 유지
- 화면 타입, 최근 이력 호환성 검사와 빈칸 표시 보완

### 제외

- 기존 값 수정·삭제
- 성적서 관리의 검사항목 등록 규칙 변경
- 측정결과 숫자 규칙 변경

## 완료 조건

- [x] 신규 행에 측정값만 입력해 저장할 수 있다.
- [x] 기준치수·공차 빈 값은 DB와 이력에 NULL로 저장된다.
- [x] 입력된 공차는 숫자 및 하한≤상한 검증을 유지한다.
- [x] 인쇄와 과거 이력에서 NULL은 빈칸으로 표시된다.

## 현재 구현 조사

- 관련 route/component: 결과 입력 sheet, inspection report actions/types
- 관련 Supabase table: `inspection_report_items`, `inspection_measurement_run_items`
- 관련 RPC: `save_inspection_measurement_entry`, `save_inspection_measurement_run`
- 문서와 구현의 차이: 화면의 빈 행 허용 의도와 DB NOT NULL 제약이 불일치한다.

## 설계

- 신규 행의 세 규격 값은 각각 선택 입력으로 처리한다.
- 공차가 둘 다 있을 때만 순서를 비교한다.
- 빈 값은 이력까지 NULL로 보존한다.
- 기존 RLS와 security definer 내부 소유권 검증을 유지한다.

## 결과

- 변경: 두 검사항목 테이블의 기준치수·공차를 nullable로 완화하고, 결과 저장 RPC와 서버 검증이 빈 문자열을 NULL로 처리하도록 변경했다. 화면상 보이지 않는 제로폭 문자와 부호만 남은 미완성 공차도 빈 값으로 정규화한다.
- 검증: `npm run lint`, `npx tsc --noEmit`, `git diff --check` 통과. 원격 migration 적용 후 dry run에서 `upToDate: true`를 확인했다.
- 미실행: 로그인된 브라우저에서 빈 규격 신규 행을 실제 저장하는 수동 시나리오는 실행하지 않았다.
- 남은 위험/후속 작업: 기존 UI 상태에서 재시도할 때는 페이지를 새로고침한 뒤 저장 결과를 확인해야 한다.
