## 배경과 목적

결과입력 화면에서 검사성적서가 많아질수록 원하는 성적서를 찾기 어렵고, 항상 노출되는 조회조건은 좁은 작업영역을 더 차지할 수 있다. 조회조건을 기본 접힘 상태로 제공하고 검색 결과만 목록에 표시하며, 목록과 검사성적서 본문의 품명 의미를 품목상세명으로 일관되게 맞춘다.

## 범위

### 포함

- 결과입력 화면 상단에 기본적으로 접힌 조회조건 토글 추가
- 펼쳤을 때 통합 검색어 입력, 조회, 초기화 제공
- 기종, 품목상세코드(품번/도번), 품목상세명과 고객명을 대상으로 서버 재조회
- 검색 중, 검색 결과 없음과 조회 오류 처리
- 검사성적서 목록에서 `미판정`과 `시료` 정보 제거
- 검사성적서 목록에 품목상세명 표시
- 결과입력 및 인쇄 양식의 `품명` 값을 품목상세명으로 변경
- 과거 이력 조회 양식도 이력 시점의 품목상세명을 `품명`으로 표시

### 제외

- 성적서관리 화면의 품명·품목상세명 표기 변경
- 검사성적서 DB 스냅샷 컬럼 변경 또는 기존 데이터 변환
- 검색조건 URL 저장과 페이지네이션
- 검색 유형별 선택박스 추가

## 설계

### UI와 반응형

- 모바일: `조회조건` 토글 한 줄만 기본 노출하고 펼치면 검색 입력과 버튼을 세로 배치한다.
- 태블릿: 검색 입력이 남은 너비를 사용하고 조회·초기화 버튼은 우측에 배치한다.
- 데스크톱: 접힌 상태에서는 결과 건수와 조회조건 토글만 표시해 측정 양식의 세로 공간을 보존한다.
- 로딩/빈 상태/오류/권한: 조회 중 버튼 비활성화, 목록 로딩 안내, 검색 결과 없음과 서버 오류를 목록 영역에 표시한다.
- 접근성: 토글의 `aria-expanded`와 연결 영역, 검색 label, Enter 조회와 키보드 focus를 제공한다.

### Server/Client 경계

- Server Component/Action: 인증과 검색어 길이를 검증하고 `inspection_reports`를 최신순으로 재조회한다.
- Client Component/Zustand: 조회조건 접힘, 검색어, 조회 결과와 선택 성적서는 지역 상태로 관리한다. 검색으로 사라진 선택은 첫 결과로 이동한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 기존 컬럼과 인덱스를 사용하며 부분일치 검색 구조는 변경하지 않는다.
- RLS 정책: 기존 authenticated select 정책을 유지한다.
- Storage bucket/path/policy: 기존 최초 로딩 데이터의 서명 URL을 선택 성적서에 재연결한다.
- migration과 rollback: migration 없음. 신규 검색 action과 UI 상태를 제거하면 기존 전체 목록 표시로 복구된다.

## 변경 계획

1. 결과입력 전용 성적서 통합검색 서버 함수를 추가한다.
2. 기본 접힘 조회조건과 조회·초기화 동작을 결과입력 화면에 추가한다.
3. 검색 결과 목록의 선택 상태와 기존 입력 행 상태를 성적서 seq 기준으로 유지한다.
4. 목록에서 미판정·시료를 제거하고 품목상세명을 표시한다.
5. 현재·과거 검사성적서 양식의 품명을 품목상세명으로 통일한다.

## 위험과 승인 사항

- 검색은 통합검색 한 개 입력으로 기종, 품번/도번, 품목상세명과 고객명을 찾는다.
- 조회조건은 화면을 열 때 접혀 있으며 사용자가 펼친 상태는 해당 탭이 마운트된 동안만 유지한다.
- 검색 결과에서 제외된 성적서의 작성 중 입력값은 탭을 닫지 않는 동안 `rowsByReport`에 유지된다.
- DB 변경은 없다.
