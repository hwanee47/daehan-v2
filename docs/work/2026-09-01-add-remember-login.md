## 배경과 목적

현재 Supabase SSR 기본 설정은 로그인 세션 쿠키를 장기간 유지하지만 사용자가 이를 선택할 수 없다. 로그인 화면에 자동 로그인 선택을 제공하고, 선택 여부에 따라 브라우저 종료 후 세션 유지 정책을 명확히 적용한다.

## 범위

### 포함

- 로그인 화면에 `자동 로그인` 체크박스 추가
- 선택 시 인증 세션을 30일 동안 유지
- 미선택 시 브라우저 세션 동안만 인증 쿠키 유지
- 로그인 및 프록시의 쿠키 만료 정책 통일
- 비밀번호를 저장하지 않고 세션 유지 선택값만 별도 쿠키에 저장
- 기존 로그인 검증, 리다이렉트와 로그아웃 동작 유지

### 제외

- 이메일 또는 비밀번호 자동 완성값 직접 저장
- DB, Supabase Auth 설정, RLS 변경
- 기기 목록과 원격 세션 강제 종료 기능
- 30일을 사용자가 직접 선택하는 UI

## 완료 조건

- [x] 자동 로그인 선택 상태에 따라 인증 쿠키가 영속 또는 세션 쿠키로 설정된다.
- [x] 자동 로그인 선택 시 브라우저를 다시 열어도 유효한 세션이면 로그인 상태가 유지된다.
- [x] 미선택 시 브라우저 세션 종료 후 로그인 정보가 유지되지 않는다.
- [x] 비밀번호나 인증 토큰을 별도 localStorage/Zustand에 저장하지 않는다.
- [x] 서버 렌더링과 proxy 세션 갱신이 같은 만료 정책을 사용한다.

## 현재 구현 조사

- 관련 route/component: `src/app/login/login-form.tsx`, `src/app/login/actions.ts`, `src/lib/supabase/server.ts`, `src/proxy.ts`
- 관련 Supabase table/bucket: Supabase Auth 세션만 사용, DB와 Storage 변경 없음
- 재사용할 기존 패턴: `@supabase/ssr`의 cookie adapter와 `proxy.ts` 세션 갱신
- 문서와 구현의 차이: 현재 `@supabase/ssr` 기본 쿠키 최대 수명은 400일이며 사용자 선택 UI가 없다.

## 설계

### UI와 반응형

- 모바일: 비밀번호 입력 아래에 44px 이상 터치 가능한 체크박스 행 표시
- 태블릿: 로그인 카드 너비 안에서 동일 배치
- 데스크톱: 기존 로그인 버튼 위에 동일 배치
- 로딩/빈 상태/오류/권한: 로그인 오류 시 이메일과 자동 로그인 선택 상태 유지
- 접근성: native checkbox, 연결된 label, 키보드 Space 전환 지원

### Server/Client 경계

- Server Component/Action: Server Action이 선택값을 검증하고 인증 쿠키 정책과 선택 쿠키를 설정
- Client Component/Zustand: 체크박스는 form 입력으로만 관리하며 Zustand에 저장하지 않음

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 해당 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: migration 없음. 쿠키 정책 옵션과 UI 제거로 롤백 가능

## 변경 계획

1. 공통 자동 로그인 쿠키 이름과 30일 만료 옵션을 정의한다.
2. 서버 Supabase client가 선택값 또는 요청 쿠키에 맞는 만료 정책을 사용하게 한다.
3. proxy가 같은 선택 쿠키를 읽어 세션 갱신 시 정책을 유지하게 한다.
4. 로그인 폼과 Server Action에 자동 로그인 체크를 연결한다.
5. 인증 경계, 쿠키 옵션과 반응형·키보드 흐름을 검증한다.

## 위험과 승인 사항

- 자동 로그인은 공유 PC에서 계정 접근 시간이 길어질 수 있으므로 기본값은 미선택으로 둔다.
- 선택 시 30일은 마지막 세션 갱신을 기준으로 연장되는 방식이다.
- Supabase refresh token은 기존 인증 쿠키 안에만 유지하며 별도 저장하지 않는다.

## 결과

- 변경: 로그인 화면에 자동 로그인 선택을 추가하고 서버 client와 proxy가 선택값에 따라 인증 쿠키를 30일 또는 브라우저 세션 쿠키로 설정하도록 구현했다.
- 검증: 전체 ESLint, TypeScript, `git diff --check`, Next.js webpack 프로덕션 빌드가 통과했다. 로그인 오류 상태와 쿠키 정규화 분기를 코드 검토했다.
- 미실행: 실제 브라우저 종료·재실행을 포함한 360px, 768px, 1280px 수동 로그인 테스트는 수행하지 않았다.
- 남은 위험/후속 작업: 기존에 발급된 장기 쿠키는 사용자가 다시 로그인하거나 토큰이 갱신될 때 새 정책으로 전환된다. 빌드 중 Supabase SDK가 Node.js 20 지원 중단 예정 경고를 출력했다.
