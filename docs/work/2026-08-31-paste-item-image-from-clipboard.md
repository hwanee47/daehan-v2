# 품목 이미지 클립보드 붙여넣기

## 배경과 목적

화면 캡처 후 파일로 저장하고 다시 선택하는 과정 없이, 품목 및 품목상세 이미지 관리 팝업에서 클립보드 이미지를 `Ctrl+V` 또는 `⌘V`로 바로 첨부하고 저장할 수 있도록 한다.

## 범위

### 포함

- 이미지 관리 팝업이 열린 동안 클립보드의 이미지 붙여넣기 감지
- 붙여넣은 이미지를 기존 파일 선택과 동일한 선택 파일 및 미리보기로 반영
- JPEG, PNG, WebP 및 5MB 제한을 붙여넣기 시점에 즉시 검증
- 붙여넣기 성공·지원하지 않는 형식·용량 초과 안내
- 기존 `이미지 등록` 또는 `이미지 교체` 버튼으로 최종 저장
- 품목과 품목상세 이미지 모두 동일하게 지원

### 제외

- 붙여넣는 즉시 서버에 자동 저장
- 클립보드 텍스트나 HTML URL을 이미지로 변환
- 여러 이미지를 한 번에 등록
- API, Supabase Storage 정책과 DB 구조 변경

## 완료 조건

- [x] 화면 캡처 이미지 파일을 붙여넣으면 기존 미리보기 상태에 반영된다.
- [x] 붙여넣은 이미지는 기존 저장 버튼과 FormData 업로드 흐름을 사용한다.
- [x] 이미지가 아닌 클립보드 내용은 처리하지 않는다.
- [x] 지원하지 않는 이미지 형식과 5MB 초과 이미지는 서버 전송 전에 안내한다.
- [x] 파일 선택 방식도 같은 검증 함수를 사용한다.

## 현재 구현 조사

- 관련 route/component: `src/app/(app)/master/items/item-management.tsx`, `src/app/api/item-images/route.ts`
- 관련 Supabase table/bucket: `items.image_path`, `item_details.image_path`, 기존 비공개 품목 이미지 bucket; 변경 없음
- 재사용할 기존 패턴: 선택한 `File`의 object URL 미리보기와 `/api/item-images` FormData 업로드
- 문서와 구현의 차이: 현재 파일 input으로 선택한 파일만 `file` 상태에 반영된다.

## 설계

### UI와 반응형

- 모바일: 파일 선택 아래에 기기에서 지원되는 경우 붙여넣기 안내를 표시한다. 모바일 OS의 클립보드 이미지 지원 여부는 브라우저에 따른다.
- 태블릿: 기존 팝업 폭과 버튼 배치를 유지한다.
- 데스크톱: `Ctrl+V`/`⌘V` 안내를 표시하고 팝업이 열린 동안 어느 요소에 포커스가 있어도 이미지 붙여넣기를 감지한다.
- 로딩/빈 상태/오류/권한: 붙여넣기는 로컬 미리보기까지만 수행하고, 실제 업로드의 로딩·오류·권한 처리는 기존 API 흐름을 유지한다.
- 접근성: 안내 문구와 성공 상태를 `aria-live` 영역으로 제공하며 파일 input을 계속 사용할 수 있게 유지한다.

### Server/Client 경계

- Server Component/Action: 변경 없음. 기존 Route Handler가 업로드 파일을 다시 검증한다.
- Client Component/Zustand: ClipboardEvent에서 첫 번째 이미지 파일만 읽어 이미지 관리 팝업의 지역 `file` 상태에 저장한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 변경 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 기존 경로, MIME, 크기 및 관리자 권한 검증을 그대로 사용한다.
- migration과 rollback: migration 없음. 클라이언트 붙여넣기 처리와 안내를 제거하면 기존 파일 선택 방식으로 복구된다.

## 변경 계획

1. 파일 선택과 붙여넣기가 함께 사용하는 클라이언트 이미지 검증 함수를 만든다.
2. 이미지 관리 팝업 수명 동안 `paste` 이벤트를 등록하고 첫 이미지 파일을 반영한다.
3. 붙여넣기 안내와 선택 성공 상태를 추가한다.
4. 파일 선택·붙여넣기·교체·삭제 흐름의 회귀 여부를 검증한다.

## 위험과 승인 사항

- 브라우저나 운영체제가 캡처 이미지를 ClipboardEvent의 파일로 제공하지 않으면 붙여넣을 수 없으며 파일 선택은 계속 사용할 수 있다.
- 여러 이미지가 클립보드에 있어도 첫 번째 이미지만 사용한다.
- 보안상 붙여넣기만으로 서버 저장하지 않고 사용자가 저장 버튼을 눌러 확정한다.
