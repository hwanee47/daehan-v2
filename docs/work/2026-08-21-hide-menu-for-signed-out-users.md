## 배경과 목적

현재 홈 헤더는 로그인하지 않은 사용자에게도 `검사성적서` 주요 메뉴를 표시한다. 인증되지 않은 사용자에게는 업무 메뉴를 노출하지 않고 로그인 진입점만 제공한다.

## 범위

### 포함

- 홈 Server Component에서 Supabase 인증 사용자 존재 여부를 명시적으로 반환
- 비로그인 상태에서는 중앙 `주요 메뉴` 내비게이션 전체를 렌더링하지 않음
- 로그인 상태에서는 기존 `검사성적서` 메뉴와 관리자 전용 `기준정보` 메뉴를 기존 조건대로 표시
- 비로그인 상태의 브랜드 링크와 우측 `로그인` 버튼은 유지

### 제외

- `/inspection-reports` 등 개별 URL의 직접 접근 차단 또는 로그인 리다이렉트
- Supabase RLS, 인증 방식, 세션 저장 또는 DB schema 변경
- 홈 본문 콘텐츠 숨김
- 로그인·회원가입 화면 변경

## 완료 조건

- [x] 비로그인 홈 헤더에 주요 업무 메뉴가 표시되지 않는다.
- [x] 비로그인 홈 헤더에 브랜드와 로그인 진입점은 표시된다.
- [x] 일반 로그인 사용자는 검사성적서 메뉴를 볼 수 있다.
- [x] 관리자 로그인 사용자는 검사성적서와 기준정보 메뉴를 볼 수 있다.
- [x] 헤더의 3열 정렬이 메뉴 부재 상태에서도 모바일·태블릿·데스크톱에서 유지된다.

## 현재 구현 조사

- 관련 route/component: `src/app/page.tsx`, `src/app/reference-information-menu.tsx`
- 관련 Supabase table/bucket: `auth.users` 인증 상태와 기존 `public.users.role` 조회를 재사용하며 DB 변경은 없다.
- 재사용할 기존 패턴: 홈 Server Component의 `supabase.auth.getUser()` 결과와 `userName` 조건부 사용자 메뉴를 재사용한다.
- 문서와 구현의 차이: 해당 없음.

## 설계

### UI와 반응형

- 모바일: 브랜드와 로그인 버튼을 양 끝에 유지하고 중앙 메뉴 영역은 비운다.
- 태블릿: 모바일과 동일한 조건으로 업무 메뉴만 숨긴다.
- 데스크톱: 로그인 전에는 브랜드와 로그인 버튼만 보이고, 로그인 후 기존 중앙 메뉴를 표시한다.
- 로딩/빈 상태/오류/권한: Server Component에서 인증 상태가 확정된 결과만 렌더링하므로 별도 로딩 상태는 없다. 사용자 조회 실패 또는 세션 없음은 비로그인으로 처리한다.
- 접근성: 내용 없는 `nav`를 만들지 않으며 로그인 링크의 기존 접근성 이름을 유지한다.

### Server/Client 경계

- Server Component/Action: `src/app/page.tsx`에서 인증 여부를 판별하고 주요 메뉴 렌더링을 조건부 처리한다.
- Client Component/Zustand: 변경 없음. 관리자 드롭다운은 기존 Client Component를 유지한다.

### 데이터와 Supabase

- schema 변경: 해당 없음.
- PK/FK/index: 해당 없음.
- RLS 정책: 변경 없음. 메뉴 숨김은 보안 경계가 아니며 기존 RLS를 대체하지 않는다.
- Storage bucket/path/policy: 해당 없음.
- migration과 rollback: 해당 없음. 롤백은 홈의 주요 메뉴 조건부 렌더링을 제거한다.

## 변경 계획

1. 현재 사용자 프로필 조회 결과에 명시적인 로그인 여부를 포함한다.
2. 로그인된 경우에만 중앙 주요 메뉴 `nav`를 렌더링한다.
3. 기존 일반 사용자·관리자 메뉴 조건이 유지되는지 정적 검사와 브라우저에서 확인한다.

## 위험과 승인 사항

- 이번 변경은 메뉴 가시성만 제어하며 직접 URL 접근 권한을 강화하지 않는다.
- 홈 헤더의 인증 기반 노출 동작 변경에 대한 명시적 승인이 필요하다.

## 결과

- 변경: 홈 인증 조회 결과에 `isAuthenticated`를 추가하고, 로그인된 경우에만 주요 메뉴를 렌더링했다. 사용자 메뉴는 세 번째 grid 열에 고정해 비로그인 레이아웃을 유지했다.
- 검증: `git diff --check`, `npm run lint`, `npx tsc --noEmit`, `npx next build --webpack`을 통과했다. 로그아웃 브라우저에서 360px, 768px, 1280px 모두 주요 메뉴 없음, 검사성적서 링크 없음, 브랜드·로그인 링크 표시, 전체 페이지 overflow 없음과 콘솔 오류 없음을 확인했다.
- 미실행: 관련 단위/통합 테스트 환경이 없고 일반 사용자·관리자 테스트 계정 로그인을 수행하지 않아 로그인 상태의 브라우저 검증은 미실행했다. 해당 분기는 기존 `isAdmin` 조건과 정적 검사로 확인했다.
- 남은 위험/후속 작업: 메뉴 숨김은 보안 경계가 아니므로 직접 URL 접근 제한이 필요하면 별도 작업에서 route authorization을 추가해야 한다.
