## 배경과 목적

성적서 관리에서 검사항목을 입력할 때 활성 `U0003` 코드와 품목별 오차범위를 함께 참고할 수 있도록 간단한 표시가 필요하다. 사용자가 기준치수를 입력하면 해당 숫자와 일치하는 오차범위를 바로 확인할 수 있게 한다.

## 범위

### 포함

- 성적서 관리 초기 데이터 조회에 활성 `U0003` 코드 상세를 포함한다.
- 자동완성 결과를 U0003 코드명의 숫자 오름차순으로 나열하고 각 행에 적용 오차범위를 함께 표시한다.
- 기준치수 입력 행에는 현재 일치한 구간과 하한·상한 편차를 짧게 표시한다.
- 등록 및 수정 화면에서 동일하게 표시한다.

### 제외

- `U0003` 코드 등록·수정 기능
- `U0003` 코드 선택값 저장
- `item_tolerance_ranges`와 `code_details` 사이의 DB 관계 추가
- 테이블, 컬럼, RLS 및 migration 변경

## 설계

### UI와 반응형

- 모바일: 코드명과 오차범위를 줄바꿈 가능한 짧은 참고 문구로 표시한다.
- 태블릿: 코드와 범위를 같은 줄에 배치하고 너비 부족 시 자연스럽게 줄바꿈한다.
- 데스크톱: 검사항목 안내문 아래 또는 기준치수 입력과 가까운 위치에 작은 보조 텍스트로 표시한다.
- 로딩/빈 상태/오류/권한: `U0003` 코드가 없으면 코드 부분을 표시하지 않고, 오차범위 없음은 기존 안내를 유지한다.
- 접근성: 색상에 의존하지 않고 `코드`, `오차범위` 텍스트 레이블을 제공한다.

### Server/Client 경계

- Server Component/Action: 초기 성적서 데이터 조회에서 활성 `U0003` 코드를 함께 가져온다.
- Client Component/Zustand: 기존 지역 상태의 기준치수와 오차범위 결과를 조합해 참고 문구를 계산한다. Zustand 변경은 없다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 변경 없음
- RLS 정책: 변경 없음. 기존 인증 사용자 코드 조회 정책 사용
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: migration 없음. U0003 조회 및 UI 표시를 제거하면 된다.

## 변경 계획

1. `InspectionCodeOption`의 코드 그룹 타입과 초기 코드 조회에 `U0003`을 추가한다.
2. 검사항목 영역에서 활성 U0003 코드명을 간단히 표시한다.
3. 각 기준치수 입력값과 일치한 오차범위를 계산해 코드 옆 참고 문구로 표시한다.
4. 기존 자동완성과 공차 입력 회귀를 검증한다.

## 위험과 승인 사항

- 현재 DB 구조에는 `U0003` 코드 하나와 특정 오차범위를 연결하는 FK나 코드 컬럼이 없다. 따라서 이번에는 코드와 범위를 참고 정보로 나란히 표시하며 서로 매핑하거나 저장하지 않는다.
- `U0003` 코드별로 서로 다른 오차범위를 연결해야 한다면 별도의 DB 설계와 승인이 필요하다.

## 결과

- 변경: 성적서 초기 코드 조회에 활성 `U0003`을 포함하고, U0003 코드 전체를 기준으로 코드명에서 숫자를 추출해 오차범위를 연결했다. 자동완성 후보는 코드명 숫자 오름차순으로 `[코드명] 0.5 < 치수 <= 6 -0.1/0.1` 형식이며, 범위를 찾지 못한 코드도 `오차범위 없음`으로 표시한다.
- 검증: `npm run lint`, `npx tsc --noEmit`, `npx next build --webpack`, `git diff --check` 통과
- 미실행: 인증된 실제 화면의 모바일·태블릿·데스크톱 시각 검증은 로그인 상태가 없어 수행하지 못했다.
- 남은 위험/후속 작업: 원격 DB에 활성 `U0003` 상세 코드가 없으면 코드 표시는 생략된다. 코드별 오차범위 매핑은 별도 DB 관계가 필요하다.
