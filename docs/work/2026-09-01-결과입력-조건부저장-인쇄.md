## 배경과 목적

결과 입력 화면에서 인쇄할 때 신규 입력이나 수정 내용이 있으면 해당 내용을 먼저 저장해야 인쇄물과 최신 이력이 일치한다. 아무것도 변경하지 않은 상태에서는 불필요한 중복 이력을 만들지 않고 바로 인쇄한다.

## 범위

### 포함

- 검사성적서를 불러온 시점의 입력 기준값 보관
- 측정결과, 비고, 재질, 경도, 열처리, 제품구분과 신규 검사항목의 변경 여부 감지
- 변경된 상태에서 인쇄 클릭 시 `print` 유형으로 저장하고 성공한 경우에만 인쇄
- 변경 없는 상태에서 DB 저장 없이 즉시 인쇄
- 수동 저장 성공 후 현재 값을 새 기준값으로 갱신
- 저장 실패 시 인쇄 중단 및 기존 오류 메시지 표시
- 인쇄 저장 중 버튼 중복 실행 방지

### 제외

- DB 스키마, RLS와 RPC 구조 변경
- 과거 이력 읽기 전용 화면의 인쇄 방식 변경
- 인쇄 레이아웃 변경

## 완료 조건

- [x] 신규 측정값 입력 후 인쇄하면 이력이 한 번 저장된 뒤 인쇄된다.
- [x] 기존 입력값 수정 후 인쇄해도 저장 성공 후 인쇄된다.
- [x] 검사성적서를 불러온 뒤 아무것도 변경하지 않고 인쇄하면 새 이력이 생성되지 않는다.
- [x] 인쇄 전 저장이 실패하면 인쇄창이 열리지 않는다.
- [x] 수동 저장 직후 변경 없이 인쇄하면 중복 저장하지 않는다.

## 현재 구현 조사

- 관련 route/component: `inspection-measurements/inspection-measurement-sheet.tsx`, `inspection-reports/actions.ts`
- 관련 Supabase table: 기존 측정결과·측정이력 테이블만 사용, 변경 없음
- 재사용할 기존 패턴: `saveInspectionMeasurements`, `save_inspection_measurement_entry`, `event_type = print`
- 문서와 구현의 차이: 현재 인쇄 버튼은 저장 상태와 무관하게 `window.print()`만 호출하며 Server Action은 event type을 항상 `save`로 고정한다.

## 설계

### UI와 반응형

- 기존 상단 `+` 작업 메뉴의 인쇄 버튼 위치와 크기를 유지한다.
- 변경 상태에서 인쇄하면 버튼을 비활성화하고 저장 중 상태를 사용한다.
- 저장 오류는 현재 결과 입력 상단 오류 영역에 표시한다.
- 인쇄 레이아웃과 반응형에는 변화가 없다.

### Server/Client 경계

- Client Component: 정규화한 입력 스냅샷을 성적서별로 보관하고 현재 값과 비교한다. 인쇄 의도를 저장 요청과 연결하고 저장 성공 후 인쇄창을 연다.
- Server Action: 제출한 `eventType`을 `save` 또는 `print`로 검증해 기존 RPC에 전달한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 변경 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음. 앱 코드 롤백만으로 복원 가능하다.

## 변경 계획

1. 성적서별 입력 기준 스냅샷과 변경 감지 구현
2. 인쇄 버튼을 조건부 저장 제출 또는 즉시 인쇄로 분기
3. Server Action의 save/print event type 검증 및 전달
4. 저장 성공·실패 후 인쇄 제어와 기준값 갱신
5. 정적 검사와 직접 URL·탭 흐름 검증

## 위험과 승인 사항

- 인쇄 전 저장은 측정 이력을 한 건 생성하며 event type은 `print`로 기록한다.
- 브라우저 인쇄창은 비동기 저장 성공 후 열리므로 실제 브라우저에서 팝업 동작을 확인해야 한다.
- DB 변경은 없다.

## 결과

- 변경: 성적서별 입력 기준 스냅샷과 변경 감지를 추가했다. 인쇄 시 변경이 있으면 `print` 이력을 저장한 뒤 인쇄하고, 변경이 없으면 바로 인쇄한다. 수동 저장 성공 시 기준값을 갱신한다.
- 검증: `npm run lint`, `npx tsc --noEmit`, `npx next build --webpack`, `git diff --check` 통과.
- 미실행: 로그인된 브라우저에서 실제 인쇄창과 측정 이력 생성 건수를 확인하는 수동 시나리오는 실행하지 않았다.
- 남은 위험/후속 작업: 브라우저별로 비동기 저장 직후 `window.print()` 허용 동작을 확인해야 한다.
