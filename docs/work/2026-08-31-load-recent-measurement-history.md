## 배경과 목적

같은 검사성적서를 반복 측정할 때 직전 측정값을 참고하거나 일부 값만 수정해 새 회차로 저장하려면 기존 값을 다시 입력해야 한다. 결과입력 화면에서 선택한 검사성적서의 최근 측정이력 5건을 간단한 목록으로 확인하고, 호환되는 이력을 현재 입력 폼에 복사해 신규 회차 작성을 시작할 수 있도록 한다.

## 범위

### 포함

- 결과입력 화면에 `최근 이력` 버튼 추가
- 버튼을 누를 때 선택한 검사성적서의 최근 이력 최대 5건 서버 조회
- 회차, 저장일시와 구분을 포함한 목록형 선택 UI
- 선택한 이력의 측정결과 1~10과 비고를 현재 입력 폼에 복사
- 복사 후 사용자가 값을 수정하고 기존 `측정결과 저장`으로 신규 회차 생성
- 현재 검사항목 구조와 이력 구조의 호환성 검증 및 불일치 안내
- 로딩, 빈 상태와 조회 오류 처리

### 제외

- 과거 이력 원본 수정 또는 삭제
- 이력을 선택하는 즉시 자동 저장
- 과거 이력의 품명, 고객명, 제품구분 등 마스터 스냅샷으로 현재 성적서 정보 덮어쓰기
- 다른 검사성적서 또는 다른 품목상세 이력 복사
- DB 테이블, 함수, RLS와 migration 변경

- [x] 호환되는 이력을 선택하면 측정값과 비고가 현재 입력란에 복사된다.
- [x] 불러오기만으로 새 이력이 생성되지 않고 저장 버튼을 눌렀을 때만 신규 회차가 생성된다.
- [x] 기존 화면 입력값이 있으면 덮어쓰기 전에 사용자에게 확인받는다.
- [x] 검사항목 개수·기준치수·공차가 다른 이력은 복사할 수 없고 이유를 안내한다.
- [x] 과거 이력 데이터는 변경되지 않는다.

## 설계

### UI와 반응형

- 모바일: `최근 이력` 버튼으로 Dialog를 열고 5개 이력을 세로 카드 목록으로 표시한다.
- 태블릿: Dialog 폭 안에서 회차·저장일시·구분과 불러오기 동작을 한 행에 배치한다.
- 데스크톱: 결과입력 하단 작업 영역에 보조 버튼을 두어 저장·인쇄 동작과 함께 접근한다.
- 로딩/빈 상태/오류/권한: 조회 중 상태, 이력 없음, 인증 및 서버 오류를 Dialog 안에서 표시한다. 선택 성적서가 없으면 버튼을 비활성화한다.
- 접근성: Dialog 제목·설명, 목록 선택, Escape 닫기, 키보드 포커스와 덮어쓰기 확인을 제공한다.

### Server/Client 경계

- Server Component/Action: 성적서 seq와 로그인 상태를 검증하고 최신순 5개 회차 및 해당 회차 항목을 조회한다. 다른 성적서의 회차를 요청하면 반환하지 않는다.
- Client Component/Zustand: Dialog 상태와 조회 결과는 지역 상태로 관리한다. 이력 항목과 현재 항목 구조를 비교하고, 측정값·비고만 `rowsByReport`에 복사한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 기존 `(inspection_report_seq, run_no desc)` 인덱스를 사용한다.
- RLS 정책: 기존 authenticated select 정책을 유지한다.
- Storage bucket/path/policy: 해당 없음. 이미지 및 마스터 스냅샷은 복사하지 않는다.
- migration과 rollback: migration 없음. 신규 조회 action과 UI를 제거하면 기존 동작으로 복구된다.

## 변경 계획

1. 선택한 성적서의 최근 회차 5건과 항목을 반환하는 서버 조회 함수를 추가한다.
2. 결과입력 하단에 `최근 이력` 버튼과 목록 Dialog를 추가한다.
3. 현재 입력값이 하나라도 있으면 덮어쓰기 확인을 거친다.
4. 현재 항목과 이력 항목의 개수, 순서, 기준치수와 공차가 모두 일치할 때 측정값과 비고만 복사한다.
5. 복사 후 수정·신규 저장, 성적서 전환과 독립 상태를 검증한다.

## 위험과 승인 사항

- 최근 5건의 범위는 현재 선택한 `검사성적서 seq`로 제한한다.
- 기준치수·공차를 포함한 검사항목 구조가 달라진 과거 회차는 현재 입력에 잘못 매핑하지 않도록 조회만 가능하고 불러오기는 차단한다.
- 빈 현재 입력도 이력 불러오기 시 값이 채워지며, 저장 전에는 DB에 반영되지 않는다.
- DB 변경은 없다.

## 결과

- 변경: 결과입력 하단에 최근 이력 버튼과 최근 5건 목록 Dialog를 추가했다. 현재 구조와 호환되는 이력의 측정값·비고만 현재 입력 상태로 복사하며 기존 입력이 있으면 덮어쓰기 확인을 표시한다. 조회와 복사 과정은 DB를 변경하지 않는다.
- 검증: `npm run lint`, `npx tsc --noEmit`, `npx next build --webpack`, `git diff --check` 통과

- 남은 위험/후속 작업: 다른 품목상세의 이력을 템플릿처럼 가져오는 기능은 별도 범위다.
