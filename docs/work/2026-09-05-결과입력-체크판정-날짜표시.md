## 배경과 목적

결과 입력의 최종판정을 성적서 양식에 어울리는 체크박스 형태로 표시하고, 납품일자와 검사일자가 브라우저 환경과 관계없이 화면에서도 `YYYY-MM-DD`로 보이면서 캘린더 선택을 지원하도록 한다.

## 범위

### 포함

- 최종판정의 합격·불합격을 사각 체크박스 형태로 디자인한다.
- 합격과 불합격은 동시에 선택되지 않도록 기존 단일 선택 동작을 유지한다.
- 납품일자와 검사일자를 화면에서 `YYYY-MM-DD` 텍스트로 고정 표시한다.
- 각 날짜 입력 우측의 캘린더 버튼으로 네이티브 날짜 선택기를 연다.
- 직접 입력, 캘린더 선택, 저장, 이력과 인쇄에서 동일한 ISO 날짜값을 사용한다.

### 제외

- DB schema 및 migration 변경
- 날짜 범위·업무일 검증
- 공통 DatePicker 컴포넌트 신규 도입
- 최종판정 저장 구조 변경

## 완료 조건

- [x] 합격·불합격이 체크박스 모양으로 표시되고 한 항목만 선택된다.
- [x] 기본 합격 선택과 저장된 판정 복원이 유지된다.
- [x] 납품일자와 검사일자가 화면에서 정확히 `YYYY-MM-DD`로 표시된다.
- [x] 두 날짜 모두 캘린더 버튼으로 날짜를 선택할 수 있다.
- [x] 인쇄 시 날짜는 `YYYY-MM-DD` 텍스트만 표시되고 캘린더 아이콘은 보이지 않는다.

## 현재 구현 조사

- 관련 route/component: `inspection-measurements/inspection-measurement-sheet.tsx`, `globals.css`
- 관련 Supabase table/bucket: 기존 `delivery_date_text`, `inspection_date`, 최종판정 코드와 저장 RPC 유지
- 재사용할 기존 패턴: 지역 상태, 서버 날짜 검증, Lucide 아이콘, native date picker
- 문서와 구현의 차이: 판정은 현재 기본 radio 모양이며 native date input의 화면 형식은 운영체제 locale에 따라 달라진다.

## 설계

### UI와 반응형

- 모바일: 성적서의 기존 최소 폭과 가로 스크롤 구조 안에서 날짜 텍스트와 캘린더 버튼을 한 줄로 유지한다.
- 태블릿/데스크톱: 기존 표 셀 너비 안에서 `YYYY-MM-DD`와 캘린더 버튼을 표시한다.
- 로딩/빈 상태/오류/권한: 기존 상태를 유지하며 잘못된 직접 입력은 기존 서버 검증 메시지로 안내한다.
- 접근성: 판정은 실제 radio semantics를 유지하면서 시각적으로 체크박스로 표현한다. 캘린더 버튼에 날짜별 접근성 이름을 제공한다.

### Server/Client 경계

- Server Component/Action: 기존 조회·저장·날짜 검증 유지
- Client Component/Zustand: 날짜 텍스트 입력과 캘린더 선택을 기존 탭별 지역 상태에 반영

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 해당 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음. UI 컴포넌트 변경을 되돌리면 된다.

## 변경 계획

1. 화면 표시용 ISO 날짜 입력을 기능 내부 컴포넌트로 만든다.
2. 납품일자와 검사일자에 동일하게 적용한다.
3. 판정 radio를 체크박스형 시각 표현으로 변경한다.
4. lint, typecheck, build와 가능한 UI 동작을 검증한다.

## 위험과 승인 사항

- 실제 입력 의미는 최종판정 한 건만 저장되어야 하므로 checkbox HTML 타입으로 바꾸지 않고 radio를 체크박스 모양으로 디자인한다.
- 날짜를 직접 입력할 때 저장 전까지 부분 문자열이 보일 수 있으며 저장 시 `YYYY-MM-DD` 유효성 검증을 적용한다.

## 결과

- 변경: 최종판정의 실제 radio semantics는 유지하면서 사각 체크박스와 체크 표시로 디자인했다. 납품일자와 검사일자는 ISO 텍스트 입력과 캘린더 버튼을 결합한 동일 컴포넌트로 변경했다.
- 검증: `git diff --check`, `npx tsc --noEmit`, `npm run lint`, `npx next build --webpack` 통과
- 미실행: 인앱 브라우저에 인증 세션이 없어 실제 데이터 화면의 viewport·키보드 수동 검증과 별도 단위/통합 테스트는 미실행. DB 변경이 없어 Supabase 정책 검증은 해당 없음.
- 남은 위험/후속 작업: `showPicker()`를 지원하지 않는 브라우저에서는 네이티브 input click fallback을 사용한다. 빌드에서 기존 Node.js 20 지원 중단 예정 경고가 출력된다.
