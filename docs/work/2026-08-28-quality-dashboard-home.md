## 배경과 목적

현재 초기 설정 안내 중심 홈을 실제 검사 업무 현황 화면으로 변경한다. 사용자가 로그인 후 등록된 성적서, 측정 여부, 당일 발생 이력, 최근 이력과 기준정보 누락을 객관적으로 확인하고 관련 화면을 탭으로 열 수 있게 한다.

## 범위

### 포함

- 기존 홈 안내·Supabase 이동 영역 제거
- 현재 날짜와 주요 화면 바로가기
- 전체 성적서, 측정 이력 없음, 오늘 측정 저장, 오늘 인쇄 현황 카드
- 측정 이력이 없는 성적서 최대 6건 표시 및 결과 입력 화면 연결
- 최근 측정 이력 최대 8건 표시 및 이력 화면 탭 연결
- 이미지 없는 품목상세, 오차범위 없는 품목, 검사항목 없는 성적서 점검 건수
- 성적서 등록, 결과 입력, 측정 이력, 품목, 오차범위 빠른 메뉴
- 로딩·빈 상태·조회 실패 상태와 workspace container 반응형

### 제외

- DB 테이블·컬럼·함수·RLS 변경
- 월별 차트, 고객별 통계와 합격률
- 사용자별 목표·알림 저장
- 홈에서 직접 등록·수정하는 기능

## 완료 조건

- [x] 로그인 후 현재 업무 현황이 한 화면에서 보인다.
- [x] `측정 이력 없음`은 저장·인쇄 측정 이력이 한 번도 없는 성적서를 의미한다.
- [x] 오늘 측정과 오늘 인쇄는 Asia/Seoul 기준 당일 이력 건수로 표시한다.
- [x] 카드와 행의 행동이 기존 업무 화면을 새 작업 탭으로 연다.
- [x] 데이터가 없거나 일부 조회가 실패해도 홈 전체가 깨지지 않는다.
- [x] 직접 URL과 작업영역 패널에서 container 반응형으로 동작한다.

## 현재 구현 조사

- 관련 route/component: `(app)/page.tsx`, workspace tab store와 기존 검사성적서·측정 이력 화면
- 관련 Supabase table/bucket: `inspection_reports`, `inspection_report_items`, `inspection_measurement_runs`, `items`, `item_details`, `item_tolerance_ranges`
- 재사용할 기존 패턴: Server Component Supabase 조회, `useUiStore.openTab`, semantic token, `Container`
- 문서와 구현의 차이: 현재 홈은 초기 환경설정용 정적 콘텐츠이며 실제 품질 업무 데이터를 사용하지 않는다.

## 설계

### UI와 반응형

- 모바일: 현황 카드 2열, 목록과 점검 영역 1열
- 태블릿: 현황 카드 4열, 주요 목록과 점검 영역 분리
- 데스크톱: 측정 이력 없음 2/3, 기준정보 점검 1/3, 최근 이력 전체 너비
- 로딩/빈 상태/오류/권한: Server 조회 결과별 빈 상태와 통합 오류 안내
- 접근성: 의미 있는 section heading, table/list label, 키보드 접근 가능한 카드와 버튼

### Server/Client 경계

- Server Component/Action: 홈 데이터 병렬 조회와 날짜 범위 계산
- Client Component/Zustand: 홈의 링크 행동만 기존 `openTab`을 호출. 대시보드 데이터를 전역 store에 복제하지 않음

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 변경 없음. 기존 인덱스 사용
- RLS 정책: 기존 select 정책 적용
- Storage bucket/path/policy: 변경 없음
- migration과 rollback: 해당 없음

## 변경 계획

1. 홈 전용 데이터 타입과 Server 조회 함수를 추가한다.
2. 대시보드 Client Component를 구현하고 기존 탭 store와 연결한다.
3. 기존 정적 홈을 대시보드로 교체한다.
4. 직접 URL·탭 패널·분할 화면과 정적 검증을 수행한다.

## 위험과 승인 사항

- 계획·할 일·마감·담당 상태를 추론하지 않는다. “측정 저장 또는 인쇄 이력이 없는 성적서”는 `측정 이력 없음`으로만 표현한다.
- 오늘 기준은 서버의 Asia/Seoul 날짜 경계를 UTC로 변환해 조회한다.
- 데이터량이 커지면 별도 집계 RPC 또는 view가 필요할 수 있으나 이번 범위에서는 기존 query만 사용한다.
