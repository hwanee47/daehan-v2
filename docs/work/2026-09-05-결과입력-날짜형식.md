## 배경과 목적

결과 입력의 납품일자와 검사일자를 동일한 `YYYY-MM-DD` 값으로 관리하고 두 필드 모두 캘린더로 선택할 수 있게 한다.

## 범위

### 포함

- 납품일자를 HTML date input으로 변경한다.
- 검사일자와 납품일자의 값 형식을 `YYYY-MM-DD`로 통일한다.
- 두 날짜의 서버 입력값을 실제 유효한 날짜인지 검증한다.
- 인쇄에서는 두 날짜를 `YYYY-MM-DD` 텍스트로 표시하고 캘린더 아이콘을 숨긴다.
- 기존 `YYYY.MM.DD`, `YYYY/MM/DD` 형태의 날짜값은 화면에서 `YYYY-MM-DD`로 정규화한다.

### 제외

- DB 컬럼 및 migration 변경
- 날짜 범위나 업무일 검증
- 날짜가 아닌 기존 자유 입력 문자열의 자동 추정

## 완료 조건

- [x] 납품일자와 검사일자에서 캘린더를 열어 날짜를 선택할 수 있다.
- [x] 저장되는 두 날짜 값이 `YYYY-MM-DD` 형식이다.
- [x] 인쇄되는 두 날짜가 `YYYY-MM-DD` 형식이며 캘린더 아이콘이 없다.
- [x] 서버에서 존재하지 않는 날짜를 거부한다.

## 현재 구현 조사

- 관련 route/component: `inspection-measurements/inspection-measurement-sheet.tsx`, `inspection-reports/actions.ts`, `globals.css`
- 관련 Supabase table/bucket: 기존 `delivery_date_text`, `inspection_date`와 저장 RPC를 그대로 사용하며 schema 변경 없음
- 재사용할 기존 패턴: 검사일자의 `type="date"`, `validDate` 서버 검증, 성적서 print CSS
- 문서와 구현의 차이: 납품일자는 현재 자유 텍스트이고 검사일자만 date input이다.

## 설계

### UI와 반응형

- 모바일: 기존 성적서 가로 스크롤 구조 안에서 date input을 유지한다.
- 태블릿: 기존 workspace container 동작을 유지한다.
- 데스크톱: 두 필드 모두 네이티브 캘린더 선택을 제공한다.
- 로딩/빈 상태/오류/권한: 기존 상태를 유지하고 잘못된 날짜는 서버 오류 메시지로 안내한다.
- 접근성: 기존 label과 날짜 입력의 네이티브 키보드 동작을 유지한다.

### Server/Client 경계

- Server Component/Action: 두 날짜를 `YYYY-MM-DD` 및 실제 달력 날짜로 검증한다.
- Client Component/Zustand: 날짜는 기존 탭별 지역 상태에 유지한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 해당 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음. 컴포넌트와 서버 검증 변경을 되돌리면 된다.

## 변경 계획

1. 날짜 표시용 정규화 helper를 추가한다.
2. 납품일자와 검사일자를 date input 및 인쇄용 ISO 텍스트로 구성한다.
3. 서버에서 두 날짜를 동일한 규칙으로 검증한다.
4. lint, typecheck와 build를 수행한다.

## 위험과 승인 사항

- 날짜로 해석할 수 없는 기존 납품일자 자유 문자열은 date input에서 빈칸으로 표시되며 사용자가 다시 선택해야 한다.
- 네이티브 date input의 화면 표기 구분자는 브라우저/운영체제에 따라 달라질 수 있지만 내부 값과 저장값, 인쇄값은 `YYYY-MM-DD`로 고정한다.
