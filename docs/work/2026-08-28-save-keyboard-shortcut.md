## 배경과 목적

업무 입력 폼에서 일반 Enter로 의도하지 않은 저장이 발생하지 않게 하고, Windows/Linux의 `Ctrl+S`와 macOS의 `Cmd+S`로 현재 활성 저장 폼을 명시적으로 저장할 수 있게 한다.

## 범위

### 포함

- 공통 저장 단축키 훅 추가
- 검사성적서 등록·수정, 측정결과 저장, 품목·품목상세, 코드그룹·상세코드, 오차범위 저장 폼 적용
- 일반 입력의 Enter 암시적 제출 차단
- textarea 줄바꿈, 버튼의 Enter 실행, 자동완성/선택 UI의 Enter 선택 유지
- 한글 IME 조합 중 Enter 무시
- 저장 중이거나 저장 버튼이 비활성화된 경우 중복 제출 차단
- 브라우저 기본 페이지 저장 단축키 차단 후 현재 활성 폼 저장

### 제외

- 로그인·회원가입·로그아웃 폼
- 조회 조건 폼의 Enter 조회
- 삭제 확인과 이미지 업로드 폼
- `Ctrl/Cmd+Shift+S` 저장 후 닫기 기능

## 완료 조건

- [x] 저장 폼의 일반 텍스트·숫자 입력에서 Enter를 눌러도 저장되지 않는다.
- [x] textarea와 열린 자동완성 선택의 Enter 동작은 유지된다.
- [x] `Ctrl+S` 또는 `Cmd+S`로 현재 활성 폼만 한 번 저장된다.
- [x] 분할 화면에서도 포커스가 있는 패널 또는 열린 Dialog의 폼만 저장된다.
- [x] 저장 중 중복 제출되지 않는다.

## 현재 구현 조사

- 관련 route/component: 검사성적서, 측정결과, 품목관리, 코드관리, 오차범위 관리
- 관련 Supabase table/bucket: 변경 없음
- 재사용할 기존 패턴: React form action과 `useActionState`
- 문서와 구현의 차이: 저장 폼마다 브라우저 기본 암시적 제출 동작을 그대로 사용하고 있다.

## 설계

### UI와 반응형

- 모바일/태블릿/데스크톱: 시각 배치 변경 없음
- 로딩/빈 상태/오류/권한: 기존 상태 유지
- 접근성: 실제 저장 버튼과 명시적 키 조합을 사용하며 입력·버튼·자동완성 키보드 조작을 보존

### Server/Client 경계

- Server Component/Action: 변경 없음
- Client Component/Zustand: `src/hooks` 공통 훅이 해당 form과 저장 submitter에만 키보드 이벤트를 연결. 전역 listener와 Zustand는 사용하지 않음

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 해당 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 변경 없음
- migration과 rollback: 해당 없음

## 변경 계획

1. form ref, Enter 차단, Ctrl/Cmd+S 제출을 제공하는 공통 훅을 추가한다.
2. 등록·수정·측정결과 저장 폼과 저장 버튼에 적용한다.
3. 자동완성, textarea, 버튼, IME 및 분할 화면 동작을 검증한다.

## 위험과 승인 사항

- 자동완성 입력의 Enter는 목록 선택을 위해 보존한다. 목록이 닫혀 있을 때도 저장 단축키로 사용하지 않는다.
- 화면별 저장 버튼 문구와 Server Action은 변경하지 않는다.
