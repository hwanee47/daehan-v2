## 배경과 목적

결과 입력 최초 화면의 최근 작업 성적서가 고정 그리드로 길게 보여 빠른 선택 흐름과 검사성적서다운 시각적 맥락이 부족하다. 검색 버튼과 최근 목록을 한 영역에서 명확히 연결하고, 실제 검사성적서를 축소한 형태의 카드를 가로로 탐색해 원하는 성적서를 빠르게 불러올 수 있게 한다.

## 범위

### 포함

- `최근 작업 성적서` 제목/설명과 `다른 검사성적서 검색` 버튼을 같은 헤더 행의 좌우에 배치
- 최근 작업 Top 5를 실제 검사성적서 표 구조를 축약한 미니 문서 카드로 표현
- 기종, 상세품명, 품번/도번과 최근 작업 시간을 카드의 핵심 정보로 표시
- 가로 카드 레일, 터치 스와이프, 마우스 드래그, 관성 스크롤과 스크롤 스냅 적용
- 드래그와 카드 클릭을 구분해 의도하지 않은 검사성적서 열림 방지
- 키보드 탐색, 포커스 표시, 이전/다음 이동 제어와 `prefers-reduced-motion` 대응
- 작업영역 너비에 따라 다음 카드가 일부 보이도록 카드 폭과 노출 개수 조정

### 제외

- 최근 작업 선정 기준 및 Top 5 조회 쿼리 변경
- 최근 측정 이력 불러오기 동작 변경
- 검사성적서 원본/측정결과 화면의 인쇄 레이아웃 변경
- DB schema, Supabase query, 권한 및 신규 UI 라이브러리 변경
- 3D 회전, 과도한 탄성 애니메이션처럼 업무 화면의 가독성을 해치는 효과

## 완료 조건

- [ ] 검색 버튼이 최근 작업 제목과 같은 줄의 우측에 표시된다.
- [ ] 최근 카드가 검사성적서 축소본처럼 인식되면서 핵심 정보가 읽힌다.
- [ ] 터치 스와이프와 마우스 드래그로 카드 레일을 자연스럽게 이동할 수 있다.
- [ ] 이동이 끝나면 가까운 카드 위치에 정렬되고, 드래그 후 카드가 잘못 열리지 않는다.
- [ ] 카드 클릭 또는 키보드 Enter/Space로 기존과 동일하게 빈 측정결과 상태의 성적서를 불러온다.
- [ ] 좁은 단일/분할 패널에서도 세로 레이아웃을 밀어내지 않고 다음 카드가 일부 노출된다.

## 현재 구현 조사

- 관련 route/component: `src/app/(app)/inspection-measurements/inspection-measurement-sheet.tsx`
- 관련 Supabase table/bucket: 기존 최근 작업 조회 결과만 사용하며 변경 없음
- 재사용할 기존 패턴: `Button`, workspace container query, 현재 `selectReport` 동작과 최근 작업 로딩/빈 상태
- 문서와 구현의 차이: 현재는 반응형 고정 그리드와 하단 별도 검색 버튼 영역이며, 드래그/스와이프 레일이 없다.

## 설계

### UI와 반응형

- 모바일/좁은 분할 패널: 카드 한 장을 약 84~88% 폭으로 노출해 다음 카드가 보이게 하고 터치 스와이프를 우선한다.
- 태블릿/중간 패널: 약 2~3장이 보이는 고정 폭 카드 레일로 구성한다.
- 데스크톱/넓은 패널: 약 3~4장이 보이며 좌우 이동 버튼과 마우스 드래그를 함께 제공한다.
- 카드: 상단 `검사성적서` 제목과 축약 승인 칸, 중단 기종/상세품명/품번·도번 표, 하단 축약 검사항목 행과 최근 작업 시간으로 구성한다. 장식용 표 요소는 스크린리더에서 제외한다.
- 동작: 네이티브 `overflow-x-auto`, scroll snap과 브라우저 관성 스크롤을 사용한다. 마우스 포인터 드래그 시 `grab/grabbing` 상태와 이동 임계값을 적용한다.
- 로딩/빈 상태/오류/권한: 기존 메시지와 조회 조건을 유지하고, 레일 높이 안에서 표시한다.
- 접근성: 카드 버튼의 이름을 유지하고, 이전/다음 버튼에 명확한 레이블을 제공하며, 키보드 포커스와 reduced motion을 지원한다.

### Server/Client 경계

- Server Component/Action: 변경 없음
- Client Component/Zustand: 현재 Client Component의 지역 ref/state만 사용한다. 탭 전역 상태를 추가하지 않는다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 해당 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 변경 없음
- migration과 rollback: 해당 없음. UI 변경 파일을 되돌리면 된다.

## 변경 계획

1. 승인 후 기존 Daehan 디자인 언어 안에서 미니 검사성적서 카드의 시각 방향 3가지를 제시하고 하나를 선택한다. (완료: 3번 축약형 선택)
2. 최근 작업 영역의 헤더와 검색 버튼을 한 행으로 재배치한다.
3. 선택한 카드 구조를 별도 지역 컴포넌트로 분리하고 가로 레일을 구현한다.
4. 터치/마우스 드래그, 스냅, 클릭 방지 임계값, 키보드와 reduced motion을 적용한다.
5. 직접 URL과 탭 작업영역의 단일·분할 화면에서 동작과 반응형을 검증한다.

## 위험과 승인 사항

- 이 작업은 신규 시각 구조와 포인터 상호작용을 포함하는 Standard 작업이므로 구현 전 승인이 필요하다.
- 드래그 중 클릭 오작동을 막되 짧은 클릭은 기존 선택 동작을 유지해야 한다.
- 별도 캐러셀 패키지는 추가하지 않고 브라우저 네이티브 스크롤을 사용해 번들 증가와 접근성 위험을 줄인다.
- Product Design 흐름에 따라 승인 후 정확히 3개의 시각 방향을 먼저 제시하며, 선택된 방향을 기준으로 구현한다.
