## 배경과 목적

품목관리에서 등록한 품목 및 품목상세 이미지를 권한을 유지한 채 원본 파일로 내려받을 수 있게 한다. UUID Storage 경로 대신 품목코드 또는 상세코드를 사용한 이해하기 쉬운 파일명을 제공한다.

## 범위

### 포함

- 인증·관리자 권한을 확인하는 이미지 다운로드 Route Handler 추가
- 품목/품목상세의 현재 `image_path`를 서버에서 재조회한 뒤 비공개 Storage 파일 다운로드
- 다운로드 파일명: `{품목코드}.{확장자}`, `{품목상세코드}.{확장자}`
- 이미지 관리 팝업과 행 더블클릭 상세 보기 팝업에 `다운로드` 버튼 추가
- 이미지 없음, 권한 없음, 파일 없음 오류 처리

### 제외

- 여러 이미지 일괄 ZIP 다운로드
- 이미지 원본 파일명 저장을 위한 DB 컬럼 추가
- 공개 bucket 또는 Storage 정책 변경
- 이미지 형식 변환·압축

## 완료 조건

- [x] 품목 이미지가 코드 기반 파일명으로 다운로드된다.
- [x] 품목상세 이미지가 상세코드 기반 파일명으로 다운로드된다.
- [x] 이미지가 없으면 다운로드 버튼이 비활성화되거나 표시되지 않는다.
- [x] 비로그인·비관리자 요청은 거부된다.
- [x] 비공개 Storage 경로와 내부 오류가 사용자에게 노출되지 않는다.

## 현재 구현 조사

- 관련 route/component: `item-management.tsx`, `/api/item-images`, item image types
- 관련 Supabase table/bucket: `items.image_path`, `item_details.image_path`, 비공개 `item-images`
- 재사용할 기존 패턴: 서버 Supabase client, 관리자 권한 확인, Storage download
- 문서와 구현의 차이: 원본 파일명은 DB에 저장하지 않으므로 코드 기반 파일명을 사용한다.

## 설계

### UI와 반응형

- 이미지 관리 팝업 하단과 상세 보기 팝업 하단에 보조 `다운로드` 버튼을 배치한다.
- 최소 44px 터치 영역과 아이콘·텍스트 접근성 이름을 유지한다.
- 다운로드 중 중복 클릭을 막고 실패 메시지를 팝업 안에 표시한다.

### Server/Client 경계

- Route Handler가 인증, 관리자 권한, 레코드와 Storage 파일을 확인하고 attachment 응답을 반환한다.
- Client Component는 다운로드 요청과 성공/실패 UI만 관리한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 해당 없음
- RLS 정책: 변경 없음. 서버 사용자 세션과 기존 정책을 사용한다.
- Storage bucket/path/policy: 비공개 `item-images`와 기존 정책 유지
- migration과 rollback: 해당 없음

## 변경 계획

1. 기존 이미지 API의 권한 패턴을 재사용해 다운로드 endpoint를 추가한다.
2. 안전한 코드 기반 파일명과 MIME 응답 헤더를 구성한다.
3. 이미지 관리 및 상세 보기 팝업에 다운로드 행동과 오류 상태를 연결한다.
4. 정적 검사와 권한·파일 없음 경계를 검증한다.

## 위험과 승인 사항

- 브라우저 보안 정책과 관계없이 다운로드되도록 서버가 `Content-Disposition: attachment`를 설정한다.
- DB 및 Storage 정책 변경은 없다.
- 승인 전에는 애플리케이션 코드를 수정하지 않는다.
