## 배경과 목적

현재 한 화면의 등록 Dialog에서 검사성적서 기본정보, 검사항목과 측정결과를 모두 입력한다. 성적서 양식과 검사항목을 준비하는 업무와 현장에서 시료별 결과를 입력하는 업무를 분리해 작업 목적을 명확히 하고, 측정 전에 성적서를 미리 준비할 수 있게 한다.

## 범위

### 포함

- `/inspection-reports`: 검사성적서 마스터와 검사항목을 조회·등록·수정·삭제하는 관리 화면
- `/inspection-measurements`: 등록된 검사성적서의 검사항목을 불러와 X1~X10 결과와 비고를 입력하는 측정 화면
- 상단 검사성적서 메뉴를 `성적서 관리`, `측정결과 입력` 2레벨 메뉴로 변경
- 두 화면을 직접 URL과 작업영역 탭에서 동일하게 제공
- 관리 화면에서 측정값 입력 UI 제거
- 관리 화면 신규 등록 시 검사항목별 빈 측정결과 행을 함께 생성
- 측정 화면에서 성적서 선택 시 기본정보, 품목 이미지, 검사항목·공차와 시료 수 표시
- 측정 상세는 첨부된 종이 검사성적서 양식의 구획, 선, 열 비율과 정보 배치를 최대한 동일하게 구현
- 시료 수에 해당하는 X열만 활성화하고 측정결과·비고 저장
- `완료` 처리 시 시료 수 범위의 모든 결과와 최종판정 필수 검증
- 완료된 성적서는 측정 화면에서 읽기 전용으로 표시하고, 관리 화면에서 상태를 `작성 중`으로 되돌린 뒤 수정 가능
- 기존에 저장된 검사성적서 및 측정결과 호환

### 제외

- DB 테이블·컬럼·RLS·migration 변경
- 제품구분·최종판정 코드 자동 등록
- 측정 장비 연동과 자동 측정값 수집
- 자동 합격·불합격 판정 계산
- 전자결재, PDF 출력과 성적서 발행 이력
- 작성·검토·승인 결재자 저장 — 현재 DB 컬럼이 없으므로 양식의 결재란은 빈 표시 영역으로만 제공
- 동시 편집 잠금 및 실시간 협업

## 완료 조건

- [ ] 관리 화면에서 기본정보와 검사항목만 등록·수정할 수 있다.
- [ ] 관리 화면 저장 시 각 검사항목에 대응하는 빈 측정결과가 생성된다.
- [ ] 측정 화면에서 검사성적서를 선택하면 등록된 검사항목과 기존 측정결과가 표시된다.
- [ ] 측정 화면의 성적서 영역이 첨부 양식의 제목·결재란·기본정보·이미지·중요항목·측정표·특기사항·최종판정 순서와 비율을 따른다.
- [ ] 시료 수에 포함되는 X열만 편집할 수 있다.
- [ ] 측정값과 비고를 임시 저장할 수 있다.
- [ ] 필수 측정값과 최종판정이 없으면 완료할 수 없다.
- [ ] 완료된 성적서는 측정 화면에서 수정할 수 없다.
- [ ] 두 화면이 직접 URL과 탭 패널, 단일·2분할에서 동일하게 동작한다.
- [ ] DB와 코드 데이터는 변경되지 않는다.

## 설계

### UI와 반응형

- 시각 기준: `/var/folders/fn/gqkhf09d0n11ty34yz_txn_r0000gn/T/codex-clipboard-009743e8-e5fd-4fe6-82ce-4975db62fb6c.png`의 626×892px 검사성적서 양식을 기준으로 한다.
- 공통: 화면 상단에 성적서 검색·선택 도구와 저장·완료 버튼을 두고, 그 아래에는 흰 종이형 성적서 canvas를 분리해 표시한다. 업무 버튼은 양식 내부에 섞지 않는다.
- 성적서 canvas: 얇은 검정 경계선, 중앙 `검 사 성 적 서` 제목, 우측 작성·검토·승인란, 기종·품명·품번/도번·고객, 업체명·납품수량·시료수·납품일자, 제품구분, 큰 도면 이미지, 재질·경도·열처리, 검사항목 표, 특기사항과 최종판정·검사자·검사일자 순서를 그대로 따른다.
- 측정표: `순번 / 기준치수 / 공차 / X1~X10 / 비고`의 2단 header와 조밀한 행 높이를 유지한다. 현재 `tolerance_min/max`는 공차 한 칸 안에 위·아래 두 줄로 표시하고, 측정값 input의 외곽선은 표 셀 경계와 겹치지 않게 한다.
- 이미지: 선택한 품목상세의 실제 이미지를 도면 영역에 `object-contain`으로 표시하며 전체화면 확대 기능을 유지한다. 이미지가 없으면 양식 구조를 유지한 안내 문구를 표시한다.
- 모바일: 종이 양식의 열 구조를 무너뜨리지 않고 최소 폭 canvas를 독립 가로 스크롤한다. 상단 성적서 선택과 저장 행동은 모바일 폭에 맞게 줄바꿈한다.
- 태블릿: canvas를 가능한 폭에 맞추고 측정표의 X열은 가로 스크롤로 접근한다.
- 데스크톱: 참고 이미지와 같은 세로형 양식 비율을 유지하되 실제 입력이 편하도록 최대 폭을 확장한다. 좁은 분할 패널에서도 canvas가 축소되어 글자가 읽히지 않게 하지 않고 독립 가로·세로 스크롤을 제공한다.
- 로딩/빈 상태/오류/권한: 선택할 성적서 없음, 검사항목 없음, 코드 없음, 저장 실패와 완료된 성적서 읽기 전용 상태를 구분한다.
- 접근성: 성적서 선택은 키보드로 가능하게 하고 측정 입력에 행·시료 번호가 포함된 접근 가능한 이름을 제공한다. 저장·완료 결과는 live region으로 알린다.

### Server/Client 경계

- Server Component/Action: 관리·측정 데이터 조회, 마스터·검사항목 저장, 측정결과 저장, 완료 조건 검증과 상태 갱신을 서버에서 수행한다.
- Client Component/Zustand: 선택한 성적서, 검색조건, 편집 중 검사항목과 측정값은 각 마운트된 패널의 React 지역 상태로 유지한다. 전역 store에는 열린 탭 관련 상태만 둔다.

### 데이터와 Supabase

- schema 변경: 해당 없음. 현재 세 테이블 구조를 그대로 사용한다.
- PK/FK/index: 변경 없음. `inspection_report_measurements.inspection_report_item_seq` 1:1 연결을 재사용한다.
- RLS 정책: 변경 없음. 현재 authenticated 조회·등록, 작성자 또는 admin 수정·삭제 정책을 따른다.
- Storage bucket/path/policy: 변경 없음. 기존 품목상세 이미지 signed URL 조회만 사용한다.
- migration과 rollback: migration 없음. 신규 route·컴포넌트와 분리된 Server Action을 되돌리면 된다.

## 변경 계획

1. 현재 공통 타입과 loader를 관리용·측정용 데이터로 구분하되 중복 query는 최소화한다.
2. 기존 관리 Dialog에서 측정값 입력을 제거하고 마스터·검사항목 저장 Action으로 분리한다.
3. 검사항목 저장 시 대응하는 빈 측정결과 행을 생성하고 기존 결과가 있는 수정에서는 항목 대응 관계를 안전하게 갱신한다.
4. `/inspection-measurements` route와 측정 전용 Client Component·Server Action을 추가한다.
5. 측정 화면에 성적서 검색·선택, 기본정보·이미지, 공차·X1~X10 입력, 임시 저장·완료를 구현한다.
6. 완료 상태 읽기 전용과 서버의 필수값 검증을 연결한다.
7. 앱 탭, 작업영역 panel loader와 상단 2레벨 메뉴에 두 화면을 등록한다.
8. lint, TypeScript, build와 직접 URL·탭·분할 화면을 검증한다.

## 위험과 승인 사항

- DB RPC를 추가하지 않으므로 마스터·검사항목·빈 측정결과 생성은 단일 DB transaction이 아니다. 신규 등록 실패 시 마스터를 보상 삭제하고, 수정 중 일부 실패는 오류를 표시해 재시도하게 한다.
- 현재 검사항목을 수정할 때 항목 행을 삭제·재생성하면 기존 측정값이 cascade 삭제될 수 있다. 측정값이 존재하는 성적서는 관리 화면에서 검사항목 구조 변경을 막고 기본정보만 수정하도록 제안한다. 측정값을 비운 뒤 항목을 다시 구성하는 기능은 이번 범위에서 제외한다.
- `status`의 기존 `draft/completed/cancelled`를 각각 `작성 중/완료/취소`로 사용한다. 별도의 `측정 중` 상태는 DB 보완 없이 추가하지 않는다.
- 자동 판정 규칙이 정의되지 않았으므로 최종판정은 사용자가 등록한 코드에서 직접 선택한다.
- 참고 양식의 작성·검토·승인란은 DB 보완 없이 값을 저장할 수 없어 시각적 빈 칸으로만 구현한다. 결재 기능이 필요하면 별도 DB 작업으로 다뤄야 한다.
- 웹 입력 화면이므로 참고 이미지의 고정 626px 크기를 그대로 복제하지는 않는다. 정보 구조, 선, 열 비율과 조밀한 표는 동일하게 유지하면서 터치·키보드 입력 크기와 가독성을 확보한다.
