## 배경과 목적

성적서 관리에서 검사항목을 작성할 때 기준치수에 맞는 공차를 오차범위 관리 화면에서 다시 찾아 입력해야 한다. 선택한 품목의 오차범위를 한 번 조회하고, 기준치수 문자열의 숫자 부분을 기준으로 일치 구간의 하한·상한 편차를 공차 기본값으로 자동 입력한다.

## 범위

### 포함

- 성적서 등록·수정 Dialog에서 선택한 품목상세의 상위 품목에 등록된 오차범위 조회
- 품목상세 선택 또는 기존 성적서 편집 시작 시 해당 품목의 오차범위를 서버에서 한 번 조회
- 기준치수 문자열에서 첫 번째 유효 숫자를 추출
  - `θ75`, `Ø75`, `⌀75` → `75`
  - `3` → `3`
  - 소수점과 부호가 있는 숫자도 인식
- `nominal_min < 숫자 ≤ nominal_max` 구간을 찾아 다음 값을 자동 입력
  - 공차 min ← `lower_deviation`
  - 공차 max ← `upper_deviation`
- 새 행의 빈 공차는 기준치수 입력과 동시에 자동 입력
- 자동 입력된 행에서 기준치수를 다시 바꾸면 새 구간 값으로 갱신하고, 일치 구간이 없으면 자동 입력값만 비움
- 등록·수정 화면의 기존 행 모두 자동 조회 대상으로 시작하고, 사용자가 공차 min 또는 max를 직접 수정한 행만 수동값으로 전환해 이후 기준치수 변경 시 덮어쓰지 않음
- 조회 중·조회 실패 상태를 짧은 안내 문구로 표시하고 수동 입력은 계속 허용

### 제외

- `item_tolerance_ranges` table·column·index·RLS 변경
- 기준치수 문자열 전체 수식 해석
- 한 문자열에 숫자가 여러 개인 경우 두 번째 이후 숫자 판정
- 저장 시 공차를 서버에서 강제로 다시 계산하거나 기존 성적서 데이터를 일괄 변경

## 완료 조건

- [x] 품목상세를 선택하면 해당 상위 품목의 오차범위만 조회된다.
- [x] `θ75`와 `75`가 동일하게 숫자 75로 판정된다.
- [x] 하한 초과·상한 이하 구간의 하한·상한 편차가 공차 min/max에 표시된다.
- [x] 구간 경계에서 하한값과 같은 수는 제외되고 상한값과 같은 수는 포함된다.
- [x] 수동으로 수정한 공차는 기준치수 변경으로 덮어쓰지 않는다.
- [x] 오차범위가 없거나 조회가 실패해도 검사항목을 수동 입력·저장할 수 있다.
- [x] 등록과 수정 Dialog 양쪽에서 동일하게 동작한다.

- 재사용할 기존 패턴: 서버 전용 Supabase client와 인증 확인, `ItemToleranceRange` 값 구조, React 지역 상태
- 문서와 구현의 차이: 오차범위 DB는 이미 `(nominal_min, nominal_max]` 규칙과 품목별 비중복 제약을 갖지만 성적서 검사항목 입력에는 연결되어 있지 않다.

## 설계

### UI와 반응형

- 모바일: 기존 검사항목 테이블 가로 스크롤과 입력 배치를 유지한다.
- 태블릿: 검사항목 제목 주변에 오차범위 조회 상태를 짧게 표시한다.
- 데스크톱: 기준치수 입력 즉시 공차 min/max 셀에 자동값을 표시한다.
- 로딩/빈 상태/오류/권한: 조회 중, 등록 범위 없음, 조회 실패를 구분하되 입력을 비활성화하지 않는다.
- 접근성: 상태 문구에 `aria-live`를 적용하고 자동 입력된 값도 일반 input 값으로 읽히게 유지한다.

### Server/Client 경계

- Server Component/Action: 인증 사용자를 확인하고 `item_detail_seq → item_seq`를 확인한 뒤 해당 품목의 오차범위만 반환한다.
- Client Component/Zustand: 조회한 범위, 행별 자동/수동 공차 상태와 숫자 추출·구간 판정을 Dialog 지역 상태로 관리한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 기존 `item_tolerance_ranges(item_seq, nominal_min)` index와 비중복 구간 제약 사용
- RLS 정책: 기존 authenticated select 정책 사용, 변경 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: migration 없음. 조회 Action과 자동 입력 로직을 제거하면 된다.

## 변경 계획

1. 품목상세 기준 오차범위 조회 Server Action과 반환 타입을 추가한다.
2. 성적서 편집 Dialog에서 품목 변경 시 범위를 조회·캐시하고 상태를 표시한다.
3. 기준치수의 첫 숫자 추출과 `(하한, 상한]` 구간 판정 유틸리티를 추가한다.
4. 행별 자동 공차 상태를 관리해 자동값 갱신과 수동값 보호를 구현한다.
5. 등록·수정, 경계값, 숫자 없는 값, 조회 실패를 검토하고 lint/typecheck/build를 수행한다.

## 위험과 승인 사항

- `M8×1.25`처럼 숫자가 여러 개인 문자열은 첫 숫자 `8`만 판정한다. 이는 이번 요청의 “숫자만 보고 판단”을 예측 가능하게 적용하기 위한 규칙이다.
- 기존 저장된 공차도 수정 화면에서 기준치수를 변경하면 새 구간 값으로 갱신한다. 단, 현재 편집 중 사용자가 공차를 직접 수정한 행은 수동값으로 보호한다.
- DB 스키마와 기존 데이터는 변경하지 않는다.
