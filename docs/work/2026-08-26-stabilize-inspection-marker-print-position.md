## 배경과 목적

검사항목 순번 마커가 화면에서는 올바르게 보이지만 인쇄 레이아웃에서 이미지 크기가 바뀌면 화면 시점의 픽셀 계산값이 남아 이미지와 마커 위치가 어긋나는 문제를 해결한다.

## 범위

### 포함

- 공통 `InspectionMarkerImage`의 마커 표시를 픽셀 기반 absolute 위치에서 SVG 비율 좌표계로 변경
- 이미지와 SVG 모두 동일한 `contain` 규칙으로 화면·전체화면·인쇄 위치 일치
- 순번 설정을 위한 클릭 좌표 계산은 기존 정규화 비율을 유지
- 이미지 크기와 비율이 다른 품목에서 마커 크기를 일관된 상대 크기로 표시

### 제외

- 기존 DB 좌표 변환 또는 migration
- 저장된 순번 좌표 재설정
- 이미지 파일 자체 수정

## 완료 조건

- [x] 같은 저장 좌표가 일반 화면·전체화면·인쇄에서 이미지의 동일한 지점을 가리킨다.
- [x] 가로형·세로형·정사각형 이미지에서 `object-contain` 여백 때문에 마커가 이동하지 않는다.
- [x] 순번 위치 설정의 이미지 클릭 및 다음 항목 자동 선택 기능이 유지된다.
- [x] 컨테이너 크기가 변경되어도 마커 표시를 별도의 resize timing에 의존하지 않는다.

## 현재 구현 조사

- 관련 route/component: `inspection-reports/inspection-marker-image.tsx` 및 이를 사용하는 관리·측정·전체화면 UI
- 관련 Supabase table/bucket: 기존 `marker_x_ratio`, `marker_y_ratio`와 품목상세 이미지 URL을 그대로 사용
- 재사용할 기존 패턴: Next Image `object-contain`, 정규화된 0~1 좌표
- 문서와 구현의 차이: 현재 마커 표시는 ResizeObserver가 계산한 화면 픽셀 box를 사용해 인쇄 레이아웃 전환 시 계산 시점에 따라 어긋날 수 있다.

## 설계

### UI와 반응형

- 모바일: SVG가 이미지와 함께 contain되어 기존 위치를 유지한다.
- 태블릿: 동일
- 데스크톱: 동일
- 로딩/빈 상태/오류/권한: 이미지 자연 크기를 읽기 전에는 마커를 숨기고 이미지 로드 후 표시한다.
- 접근성: 각 마커의 접근성 이름을 SVG `title`로 유지한다.

### Server/Client 경계

- Server Component/Action: 변경 없음
- Client Component/Zustand: 자연 이미지 크기와 편집 클릭 계산만 지역 상태로 유지한다.

### 데이터와 Supabase

- schema 변경: 해당 없음
- PK/FK/index: 해당 없음
- RLS 정책: 해당 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음

## 변경 계획

1. 이미지 자연 크기를 SVG viewBox로 사용한다.
2. 마커 좌표를 `ratio × natural size`로 SVG 원·텍스트에 표시한다.
3. 이미지와 SVG에 같은 중앙 contain 규칙을 적용한다.
4. 편집 클릭 좌표 계산과 기존 사용 화면을 회귀 검증한다.

## 위험과 승인 사항

- 마커 크기는 이미지의 짧은 변을 기준으로 계산해 고해상도 이미지에서도 지나치게 작아지지 않게 한다.
- 기존 저장 좌표와 DB는 변경하지 않는다.
