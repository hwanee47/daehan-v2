## 배경과 목적

결과 입력의 검사성적서가 자체 스크롤을 가지면서 상위 작업영역도 세로 스크롤되어 바깥 스크롤과 불필요한 하단 여백이 생기는 문제를 해결한다.

## 범위

### 포함

- 결과 입력 작업 탭의 높이를 작업영역의 남은 높이에 맞춘다.
- 결과 입력 직접 URL도 앱 작업영역 안에서 남은 높이를 사용한다.
- 검사성적서 컨테이너만 가로·세로 스크롤을 소유하도록 한다.
- 단일 화면과 분할 화면에서 같은 overflow 구조를 유지한다.

### 제외

- 다른 업무 화면의 스크롤 구조 변경
- 검사성적서 양식 크기 및 인쇄 레이아웃 변경
- DB 및 저장 동작 변경

## 완료 조건

- [x] 결과 입력에서 검사성적서 바깥의 불필요한 세로 스크롤이 생기지 않는다.
- [x] 검사성적서 내용이 화면보다 크면 성적서 컨테이너 안에서만 스크롤된다.
- [x] 직접 URL과 작업 탭 양쪽에서 동일하게 동작한다.
- [x] 분할 화면에서도 패널별 독립 스크롤과 가로 스크롤이 유지된다.

## 현재 구현 조사

- 관련 route/component: `inspection-measurements/page.tsx`, `workspace-panels.tsx`, `inspection-measurement-sheet.tsx`, `workspace-shell.tsx`
- 관련 Supabase table/bucket: 해당 없음
- 재사용할 기존 패턴: `h-full`, `min-h-0`, `flex-1`, `overflow-hidden`, `fillContainer`
- 문서와 구현의 차이: 작업영역 패널은 자체 스크롤을 소유하도록 규정되어 있으나 결과 입력 내부에도 viewport 계산 높이와 별도 스크롤이 중첩되어 있다.

## 설계

### UI와 반응형

- 모바일/태블릿/데스크톱: 결과입력 루트를 남은 높이의 flex container로 만들고 성적서 viewport만 `overflow-auto`를 유지한다.
- 단일/분할: 각 결과입력 패널 경계를 넘지 않도록 `min-h-0`와 `overflow-hidden`을 적용한다.
- 로딩/빈 상태/오류/권한: 기존 표시 유지
- 접근성: 키보드 스크롤과 focus 동작 유지

### Server/Client 경계

- Server Component: 직접 URL의 레이아웃 class만 변경
- Client Component/Zustand: 작업 패널 class와 기존 `fillContainer` 사용만 변경하며 상태 구조는 유지

### 데이터와 Supabase

- schema, PK/FK/index, RLS, Storage, migration: 변경 없음

## 변경 계획

1. 결과 입력 전용 PanelFrame을 남은 높이 기반으로 구성한다.
2. 작업 탭에서 `InspectionMeasurementSheet`에 `fillContainer`를 적용한다.
3. 직접 URL도 동일한 높이·overflow 경계를 적용한다.
4. lint, typecheck, build와 가능한 viewport 검증을 수행한다.
