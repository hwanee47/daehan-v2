## 배경과 목적

현재 작업영역 탭은 큰 상단 radius를 사용하고 열린 탭 수 제한이나 일괄 조작 도구가 없다. 탭의 시각 밀도를 높이고, 과도한 패널 마운트를 제한하며, 두 업무 화면 비교와 작업영역 집중·정리 기능을 제공한다.

## 범위

### 포함

- 탭 surface와 탭 내부 닫기 버튼의 radius를 Tailwind `rounded-sm`로 변경
- 동시에 열 수 있는 탭을 최대 5개로 제한
- 이미 열린 탭은 제한과 관계없이 다시 활성화 가능
- 6번째 새 탭 요청은 거부하고 탭 바에 접근 가능한 안내 메시지 표시
- 탭 바 오른쪽에 `전체화면`, `2분할`, `전체 닫기` 도구 버튼 추가
- 전체화면은 작업영역 전체를 Browser Fullscreen API로 전환하고 Escape 또는 같은 버튼으로 해제
- 2분할은 활성 탭을 왼쪽, 열린 순서상 다음 탭을 오른쪽에 표시하며 다음 탭이 없으면 이전 탭을 사용
- 2분할 중 탭을 선택하면 왼쪽 패널을 해당 탭으로 바꾸고 오른쪽은 가능한 한 유지
- 화면 너비가 좁은 모바일에서는 2분할을 해제하고 단일 패널로 표시
- 전체 닫기는 확인 dialog 뒤 모든 탭과 패널 상태를 제거
- 전체화면·2분할·전체 닫기 버튼의 tooltip/접근성 이름과 키보드 focus 제공

### 제외

- 분할 비율 드래그 조절
- 세 개 이상 다중 분할
- 탭 드래그 정렬
- 브라우저 새 창 또는 OS 창 분리
- 닫은 탭의 저장하지 않은 상태 복원
- DB, Supabase, 인증 또는 업무 데이터 변경

## 설계

### UI와 반응형

- 모바일: 탭 목록은 가로 스크롤, 도구는 오른쪽 고정 영역 또는 별도 행로 노출한다. 2분할 버튼은 비활성화하고 단일 패널만 표시한다.
- 태블릿: 가로 공간이 충분한 경우 2분할을 허용하되 각 패널은 최소 너비를 갖고 내부 표는 자체 가로 스크롤한다.
- 데스크톱: 탭 목록은 남은 너비를 스크롤하고 도구 세 개는 오른쪽에 고정한다. 2분할은 동일 너비 두 열을 기본으로 한다.
- 로딩/빈 상태/오류/권한: 탭 한도 안내는 `role=status`로 제공한다. 탭이 두 개 미만이면 2분할을 비활성화한다. Fullscreen API 미지원 시 전체화면을 비활성화한다.
- 접근성: 도구 버튼에 텍스트 기반 접근성 이름, `aria-pressed`, tooltip과 focus ring을 제공한다. 전체 닫기는 focus를 확인 dialog로 이동하고 취소 시 버튼으로 복귀한다.

### Server/Client 경계

- Server Component/Action: 변경 없음
- Client Component/Zustand: 최대 탭 수, 전체 닫기, 분할 여부와 보조 패널 경로를 UI store에서 관리한다. 실제 fullscreen 진입 상태는 브라우저 이벤트를 구독하는 지역 UI 상태로 관리한다.

### 데이터와 Supabase

- schema 변경: 해당 없음
- PK/FK/index: 해당 없음
- RLS 정책: 해당 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음. UI store와 탭 도구 변경을 되돌리면 기존 단일 패널 탭으로 복구된다.

## 변경 계획

1. UI store의 열린 탭 제한과 실패 결과, 전체 닫기, 분할 상태를 설계하고 persist version을 올린다.
2. 탭 surface를 `rounded-sm`로 변경하고 탭 목록·오른쪽 도구 영역을 분리한다.
3. 작업영역 shell에 fullscreen 대상 root와 데스크톱 2열 패널 배치를 추가한다.
4. 전체화면 상태를 Fullscreen API 이벤트와 동기화한다.
5. 전체 닫기 확인 dialog와 탭 한도 안내를 추가한다.
6. 모바일에서 2분할을 안전하게 단일 화면으로 제한한다.
7. 아키텍처 문서에 단일/2분할 표시 규칙과 최대 탭 수를 반영한다.
8. 정적 검사, 빌드, 탭 한도·전체화면·분할·전체 닫기와 접근성을 검증한다.

## 위험과 승인 사항

- 전체 닫기는 저장하지 않은 폼·선택·그리드 상태를 모두 제거하므로 반드시 확인 dialog를 거친다.
- Browser Fullscreen API는 사용자 동작에서만 진입할 수 있고 브라우저·권한에 따라 지원되지 않을 수 있다.
- 2분할에서는 AG Grid 두 개가 동시에 보이므로 좁은 화면과 메모리 사용량을 확인해야 한다.
- 최대 5개 제한은 현재 네 개 업무 메뉴보다 크며 향후 메뉴 추가에도 적용된다.
- 공통 작업영역 상태와 표시 규칙을 변경하는 Standard 작업이므로 이 제안에 대한 별도 승인이 필요하다.

## 결과

- 변경: 탭과 닫기 버튼을 `rounded-sm`로 바꾸고, 탭 바 오른쪽에 전체화면·2분할·전체 닫기 도구를 추가했다. Zustand persist v3에 최대 5개 제한과 안내, 2분할과 전체 닫기 상태를 추가했다. 작업영역 root를 fullscreen 대상으로 지정하고 확인 dialog도 같은 root에 렌더링한다. 2분할은 활성 패널과 인접 패널만 보이고 나머지는 마운트 상태로 숨긴다.
- 검증: `npm run lint`, `npx tsc --noEmit`, `npx next build --webpack`, `git diff --check`를 통과했고 개발 서버 홈 요청이 200으로 응답하는 것을 확인했다.
- 미실행: 브라우저 관리자 인증 세션과 다섯 번째 실제 업무 메뉴가 없어 전체화면·2분할·전체 닫기의 실제 관리자 화면 조작, 6번째 탭 차단, 360px/768px/1280px 시각 검증은 실행하지 못했다.
- 남은 위험/후속 작업: Fullscreen API가 제한된 브라우저에서는 전체화면 버튼이 비활성화된다. 현재 업무 메뉴는 네 개라 최대 5개 제한은 향후 메뉴 추가 시 사용자 흐름으로 재검증해야 한다.
