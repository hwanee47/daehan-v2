## 배경과 목적

기종별 측정이력에서 품목 수보다 실제 검사성적서 수를 확인하고, 기종에 속한 검사서와 각 검사서의 측정이력을 좌우 마스터·상세 구조로 탐색한다.

## 범위

### 포함

- 기종별 그리드의 품목 수·품목상세 수를 검사서 수로 변경
- 기종별 검사서 목록 RPC 및 검사서별 이력 조회
- 팝업 왼쪽 검사서 그리드, 오른쪽 최신 이력 그리드와 독립 페이지 처리
- 첫 검사서 자동 선택과 키보드·행 선택 지원

### 제외

- 기존 기종별·품목별 RPC 삭제
- 측정이력 데이터 변환
- 검사서 내용 및 인쇄 양식 변경

## 완료 조건

- [x] 기종별 그리드의 검사서 수가 고유 검사성적서 개수와 일치한다.
- [x] 팝업 왼쪽에서 해당 기종의 검사서를 조회한다.
- [x] 왼쪽 검사서를 선택하면 오른쪽에 해당 검사서 이력이 최신순으로 표시된다.
- [x] 좌우 목록이 각각 페이지 이동 가능하다.

## 현재 구현 조사

- 관련 route/component: 측정이력 actions, types, `InspectionMeasurementHistory`
- 관련 Supabase table/bucket: `inspection_measurement_runs`, 신규 RPC
- 재사용할 기존 패턴: security invoker RPC, AG Grid 단일 선택, 기존 성적서 보기 dialog
- 문서와 구현의 차이: 없음

## 설계

### UI와 반응형

- 작은 화면은 좌우 그리드를 세로로 쌓고 큰 화면은 약 40:60으로 분할한다.
- 각 그리드는 자체 높이와 가로 overflow를 갖는다.

### Server/Client 경계

- Server Action이 집계·검사서 목록·선택 검사서 이력을 조회한다.
- Client Component는 선택 검사서와 각 페이지 상태를 관리한다.

### 데이터와 Supabase

- schema 변경: v2 기종 집계 RPC, 기종 검사서 목록 RPC, 복합 인덱스 추가
- RLS: 기존 테이블 RLS와 security invoker 유지
- migration rollback: 신규 함수와 인덱스 drop

## 변경 계획

1. 신규 RPC와 인덱스 migration을 추가한다.
2. 타입과 서버 actions를 검사서 마스터·이력 구조로 변경한다.
3. 팝업을 좌우 AG Grid로 구현한다.
4. dry run, 원격 적용, 정적 검사를 수행한다.
