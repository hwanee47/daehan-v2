## 배경과 목적

조회조건 영역이 항상 펼쳐져 있어 좁은 화면과 분할 작업영역에서 본문 공간을 많이 차지하고, 화면별 입력·셀렉트·초기화·조회 버튼 높이가 40px와 48px로 섞여 세로 정렬이 맞지 않는다. 조회조건이 있는 업무 화면 전체를 동일한 기본 접힘 패턴으로 바꾸고 컨트롤 크기와 버튼 순서를 통일한다.

## 범위

### 포함

- 공통 조회조건 접기/펼치기 컴포넌트 추가
- 결과입력 조회조건에 공통 컴포넌트 적용
- 성적서관리 조회조건 기본 접힘 적용
- 측정이력 조회조건 기본 접힘 적용
- 품목관리 조회조건 기본 접힘 적용: 직접 URL과 탭 작업영역
- 오차범위관리 조회조건 기본 접힘 적용: 직접 URL과 탭 작업영역
- 조회 입력·커스텀 셀렉트·초기화·조회 버튼 높이를 48px로 통일
- 버튼 순서를 `초기화` 다음 `조회`로 통일
- 좁은 화면에서는 입력과 버튼을 줄바꿈하고, 넓은 화면에서는 마지막 행 또는 우측에 정렬

### 제외

- 등록·수정 Dialog 내부의 입력 및 저장 버튼 크기 변경
- 그리드 페이지 이동 버튼과 행 작업 버튼 크기 변경
- 조회 조건 항목, 검색 방식과 서버 query 변경
- DB 스키마, 데이터와 RLS 변경

## 현재 구현 조사

- 관련 route/component: `inspection-measurements/inspection-measurement-sheet.tsx`, `inspection-reports/inspection-report-management.tsx`, `inspection-measurement-history/inspection-measurement-history.tsx`, `master/items/page.tsx`, `master/tolerance-ranges/page.tsx`, `workspace-panels.tsx`
- 관련 Supabase table/bucket: 해당 없음. 기존 조회 action과 query를 그대로 사용한다.
- 재사용할 기존 패턴: 결과입력의 `조회조건` 토글, 공통 `Button`, workspace container query
- 문서와 구현의 차이: 공통 Button 기본 높이는 48px이나 일부 검색 입력과 Select는 40px다. 조회조건 접기 구현은 현재 결과입력 한 화면에만 지역 상태로 존재한다.

## 설계

### UI와 반응형

- 모바일: 높이 48px 요약 행만 기본 노출한다. 펼치면 필드는 한 열, 버튼은 한 행 또는 가용 폭에 따라 줄바꿈한다.
- 태블릿: 필드는 두 열까지 배치하고 버튼은 동일한 48px 높이로 맞춘다.
- 데스크톱: 기존 화면별 필드 너비를 유지하되 입력과 버튼의 하단선을 맞춘다.
- 로딩/빈 상태/오류/권한: 기존 상태 표시를 유지하며 pending 동안 기존과 동일하게 컨트롤을 비활성화한다.
- 접근성: native `details/summary` 기반으로 Enter·Space 조작과 상태 전달을 제공하고 장식 아이콘은 숨김 처리한다.

### Server/Client 경계

- Server Component/Action: 직접 URL의 GET 검색 폼도 사용할 수 있도록 공통 접기 컴포넌트는 서버 렌더링 가능한 native details 구조로 만든다.
- Client Component/Zustand: 별도 전역 상태를 추가하지 않는다. 열린 상태는 각 화면의 DOM 상태로만 유지한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 해당 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: migration 없음. 공통 wrapper 제거와 기존 폼 클래스 복구로 rollback 가능하다.

## 변경 계획

1. `src/components/ui`에 기본 닫힘 조회조건 wrapper를 추가한다.
2. 5개 업무 화면과 직접 URL·탭 패널의 검색 폼을 wrapper로 감싼다.
3. 검색 input, Select와 action Button을 높이 48px로 통일한다.
4. 초기화·조회 순서와 반응형 줄바꿈을 정리한다.
5. 직접 URL, 단일 패널과 25:75·50:50·75:25 분할 너비에서 접기와 크기를 검증한다.

## 위험과 승인 사항

- 조회조건은 검색값이 이미 적용된 상태로 화면을 다시 열어도 기본적으로 접혀 있다.
- 접기 상태는 브라우저 저장소에 보존하지 않는다.
- 공통 컴포넌트는 조회조건의 외형과 접기만 담당하고 각 화면의 검색 로직은 변경하지 않는다.
- DB 변경은 없다.

- 변경: native details/summary 기반 공통 조회조건 컴포넌트를 추가하고 결과입력, 성적서관리, 측정이력, 품목관리와 오차범위관리의 직접 URL·탭 화면에 적용했다. 검색 입력·Select·초기화·조회 버튼을 48px로 통일하고 버튼 순서를 초기화→조회로 정리했다.
- 검증: `npm run lint`, `npx tsc --noEmit`, `npx next build --webpack`, `git diff --check` 통과. 대상 화면의 공통 wrapper 적용과 검색 영역 내 40px 컨트롤 잔존 여부를 코드 검색으로 확인했다.
- 미실행: 기존 개발 서버가 도구의 브라우저 환경에서 연결되지 않아 실제 로그인 화면의 모바일·태블릿·데스크톱 및 분할 비율 시각 QA는 실행하지 못했다.
- 남은 위험/후속 작업: 신규 조회 화면도 같은 wrapper를 사용하도록 디자인 지침에 별도 반영할 수 있다.
