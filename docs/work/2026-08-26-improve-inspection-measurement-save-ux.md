## 배경과 목적

시료수가 없는 검사성적서도 즉시 측정결과를 입력·저장할 수 있게 하고, 상단 저장 버튼 때문에 결과 양식이 아래로 밀리고 저장을 위해 이동해야 하는 불편을 줄인다.

## 범위

### 포함

- 시료수 미입력 경고와 저장 버튼 비활성화 제거
- 시료수가 없으면 X1~X10 결과 입력을 모두 활성화
- 시료수가 있으면 현재처럼 해당 개수까지만 결과 입력 활성화
- 우측 측정영역 하단에 항상 접근 가능한 저장 작업 바 배치
- 저장 성공·실패 메시지를 하단 작업 바 가까이에 표시
- 넓은 작업영역에서 결과 양식 영역만 세로·가로 스크롤하도록 구성

### 제외

- 검사성적서 마스터의 시료수 컬럼 제거
- DB schema, RLS 또는 저장 Action 변경
- 자동 저장 기능

## 완료 조건

- [x] 시료수가 없어도 X1~X10 입력 및 측정결과 저장이 가능하다.
- [x] 시료수가 있으면 입력 가능한 X 열 수는 기존 규칙을 유지한다.
- [x] `성적서 관리에서 시료수를 입력해 주세요.` 메시지가 표시되지 않는다.
- [x] 저장 버튼이 결과 양식 위 공간을 차지하지 않고 하단 작업 바에 표시된다.
- [x] 결과 양식을 스크롤하는 동안 저장 버튼과 저장 상태를 쉽게 확인할 수 있다.
- [x] 직접 화면과 분할 패널에서 작업 바가 다른 패널을 침범하지 않는다.

## 현재 구현 조사

- 관련 route/component: `inspection-measurements/inspection-measurement-sheet.tsx`, `inspection-reports/actions.ts`
- 관련 Supabase table/bucket: 기존 measurement update만 사용하며 변경 없음
- 재사용할 기존 패턴: workspace 패널 독립 스크롤, 기존 Button과 action state
- 문서와 구현의 차이: 현재 저장 버튼은 결과 양식 위 일반 흐름에 있고, `sample_count`가 null이면 버튼과 모든 결과 입력이 비활성화된다.

## 설계

### UI와 반응형

- 모바일: 문서 흐름 하단의 sticky 작업 바로 저장 버튼을 제공하고 결과표는 기존처럼 가로 스크롤한다.
- 태블릿: 상하 레이아웃에서도 오른쪽 입력 섹션 범위 안에 하단 작업 바를 유지한다.
- 데스크톱: 우측 결과 영역을 `스크롤 가능한 양식 + 고정 하단 작업 바` 두 행으로 구성한다. 저장 버튼은 우측 끝에 둔다.
- 로딩/빈 상태/오류/권한: 저장 중 버튼 비활성화, 결과 메시지는 작업 바에 인접해 표시한다.
- 접근성: 저장 버튼의 기존 이름과 상태 전달을 유지하고 메시지에 `role=status`를 사용한다.

### Server/Client 경계

- Server Component/Action: 기존 저장 Action을 그대로 사용한다.
- Client Component/Zustand: 입력 활성화 계산과 레이아웃만 지역 컴포넌트에서 변경한다.

### 데이터와 Supabase

- schema 변경: 해당 없음
- PK/FK/index: 해당 없음
- RLS 정책: 해당 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: 해당 없음

## 변경 계획

1. 시료수 null일 때 결과 열 10개를 모두 활성화한다.
2. 시료수 경고와 저장 버튼의 시료수 기반 비활성화를 제거한다.
3. 결과 양식 스크롤 영역과 하단 저장 작업 바를 분리한다.
4. 직접 화면·분할 패널의 overflow와 저장 상태를 검증한다.

## 위험과 승인 사항

- 시료수가 비어 있으면 입력 가능 열 수를 알 수 없으므로 최대치인 X1~X10을 모두 허용한다.
- 자동 저장은 예기치 않은 저장을 피하기 위해 포함하지 않는다.
