## 배경과 목적

품목관리 화면에서 품목코드, 품목명과 모델명뿐 아니라 품목상세코드로도 필요한 품목과 상세 정보를 찾을 수 있도록 한다.

## 범위

### 포함

- 품목관리 조회조건에 `품목상세코드` 입력 추가
- 작업영역 탭의 서버 조회 action에 품목상세코드 조건 추가
- 직접 URL의 `itemDetailCode` 검색 파라미터 및 서버 조회 추가
- 품목 조건과 품목상세코드 조건을 AND 방식으로 결합
- 일치하는 품목상세와 그 상세가 속한 품목만 결과에 표시
- 초기화 시 품목상세코드 조건도 비우고 DB 재조회

### 제외

- 오차범위관리 조회조건 변경
- 품목상세명, 소재와 비고 검색 추가
- DB 스키마, 인덱스와 RLS 변경
- 페이지네이션 정책 변경

## 현재 구현 조사

- 관련 route/component: `src/app/(app)/master/items/page.tsx`, `src/app/(app)/workspace-panels.tsx`, `src/app/(app)/workspace-data-actions.ts`
- 관련 Supabase table/bucket: `items`, `item_details`; 스키마 변경 없음
- 재사용할 기존 패턴: 기존 품목 조건의 `ilike` 서버 검색과 품목별 상세 조회
- 문서와 구현의 차이: 현재 공통 조회조건 타입과 UI에는 품목상세코드가 없으며 상세 데이터는 품목 조회 후에만 읽는다.

## 설계

### UI와 반응형

- 모바일: 기존과 같이 조회조건을 한 열로 표시한다.
- 태블릿: 두 열 배치를 유지한다.
- 데스크톱: 품목코드, 품목명, 모델명, 품목상세코드와 조회 버튼을 한 행에 배치하되 패널 너비가 부족하면 반응형으로 줄바꿈한다.
- 로딩/빈 상태/오류/권한: 기존 조회 중, 빈 결과, 오류와 관리자 권한 처리를 유지한다.
- 접근성: `품목상세코드` label과 고유 id를 연결하고 키보드 form submit을 유지한다.

### Server/Client 경계

- Server Component/Action: 검색 문자열을 100자로 제한하고 escape한 뒤 `item_details.item_detail_code`를 서버에서 조회한다.
- Client Component/Zustand: 조회조건 임시값과 적용값만 패널 지역 상태로 유지하며 업무 데이터를 전역 store에 저장하지 않는다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 기존 `item_details.item_seq` 관계를 사용하며 변경 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 기존 결과 이미지 URL 생성 방식 유지
- migration과 rollback: migration 없음. 관련 UI와 query 변경을 되돌리면 기존 조회 방식으로 복구된다.

## 변경 계획

1. 공통 품목 검색 타입과 조회조건 UI에 품목상세코드를 추가한다.
2. 작업영역 서버 조회에서 상세코드 일치 행과 상위 품목을 조회한다.
3. 직접 URL 페이지에도 같은 검색 파라미터와 조건을 적용한다.
4. 복합조건, 부분 일치, 빈 결과와 초기화를 검증한다.

## 위험과 승인 사항

- 품목상세코드 조건이 있으면 우측 상세 목록에는 검색어와 일치하는 상세만 표시한다.
- 네 가지 조건은 OR가 아니라 AND로 결합한다.
- DB 구조와 기존 데이터는 변경하지 않는다.
