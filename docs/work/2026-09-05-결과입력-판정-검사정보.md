## 배경과 목적

결과 입력 검사성적서 하단에서 최종 판정, 특기사항, 검사자와 검사일자를 직접 입력하고 저장·인쇄·측정 이력에서 동일한 회차 정보를 확인할 수 있게 한다.

## 범위

### 포함

- 최종 판정을 합격/불합격으로 입력하며 값이 없을 때 합격을 기본 선택한다.
- 특기사항, 검사자, 검사일자 입력 UI를 추가한다.
- 검사자는 김현찬, 검사일자는 화면을 연 오늘 날짜를 기본값으로 사용한다.
- 현재 검사성적서와 측정 회차 스냅샷에 입력값을 저장한다.
- 측정 이력 성적서에서 저장 당시 값을 읽기 전용으로 표시한다.
- 관련 Supabase migration, 저장 RPC, 서버 검증, 타입과 조회를 갱신한다.

### 제외

- 기존 측정 이력에 대한 임의 소급 입력
- 인증 사용자 프로필과 검사자 이름 자동 연동
- 판정 자동 계산

- [x] 네 필드를 수정하고 저장 또는 인쇄할 수 있다.

## 현재 구현 조사

- 관련 route/component: `inspection-measurements`, `inspection-measurement-history`, `InspectionMeasurementSheet`, `saveInspectionMeasurements`
- 관련 Supabase table/bucket: `inspection_reports`, `inspection_measurement_runs`, `code_groups`, `code_details`; Storage 변경 없음
- 재사용할 기존 패턴: React 지역 상태, Server Action의 FormData 검증, `save_inspection_measurement_entry` RPC, 회차 스냅샷
- 문서와 구현의 차이: 없음. 과거 마스터 컬럼 일부가 제거됐고 현재 회차 테이블에는 요청 필드가 없다.

## 설계

### UI와 반응형

- 모바일: 하단 정보를 세로 배치하고 입력 너비를 확보한다.
- 태블릿: workspace container 폭에 맞춰 판정과 검사정보를 배치한다.
- 데스크톱: 기존 인쇄 성적서 하단 구조 안에 입력 필드를 배치한다.
- 로딩/빈 상태/오류/권한: 기존 결과 입력 상태를 유지하고 서버 검증 오류를 기존 상태 메시지로 표시한다.
- 접근성: 특기사항에는 label이 있는 textarea, 검사자와 검사일자에는 label이 있는 input, 판정에는 radio group을 사용한다.

### Server/Client 경계

- Server Component/Action: FormData를 재검증하고 인증·소유권 확인 후 RPC를 호출한다.
- Client Component/Zustand: 필드는 탭별 지역 상태로 관리하며 Zustand에 복제하지 않는다.

### 데이터와 Supabase

- schema 변경: `inspection_reports`에 `special_notes`, `inspector_name`, `inspection_date`를 추가하고 기존 `final_judgment_code_seq`를 사용한다. `inspection_measurement_runs`에는 네 필드와 판정 코드/이름 스냅샷을 추가한다.
- PK/FK/index: 기존 PK를 유지하고 판정 seq는 `code_details(seq)` FK를 사용한다. 신규 인덱스는 필요하지 않다.
- RLS 정책: 기존 정책과 security definer RPC의 인증·소유권 검증을 유지한다.
- Storage bucket/path/policy: 해당 없음.
- migration과 rollback: 재현 가능한 migration으로 컬럼/RPC를 추가한다. rollback은 이전 RPC 복원 후 신규 컬럼 제거이며 신규 입력값은 유실될 수 있다.
