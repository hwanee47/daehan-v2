## 배경과 목적

성적서 관리의 검사항목에서 기준치수를 직접 입력하면 해당 품목의 오차범위로 공차를 자동 입력하고 있으나, 어떤 오차범위가 조회되었는지 사용자가 확인하거나 목록에서 직접 선택할 수 없다. 고객명·업체명 입력처럼 기준치수 아래에 검색 결과를 표시해 적용할 오차범위를 쉽게 확인하고 선택할 수 있게 한다.

## 범위

### 포함

- 성적서 등록·수정 팝업의 검사항목 `기준치수` 입력란에 오차범위 자동완성 목록을 추가한다.
- 입력값에서 첫 번째 숫자를 추출해 `하한 초과, 상한 이하` 조건과 일치하는 오차범위를 검색한다.
- 검색 결과에는 적용 구간과 하한·상한 편차를 함께 표시한다.
- 결과를 선택하면 기준치수 입력값은 유지하고 해당 행의 공차 min/max를 선택한 편차로 채운다.
- 기존의 입력 즉시 자동 공차 적용과 직접 공차 수정 기능을 유지한다.
- 등록뿐 아니라 기존 성적서 수정 시에도 동일하게 동작한다.

### 제외

- 오차범위 관리 화면의 조회조건 변경
- 오차범위 테이블, 컬럼, RLS 또는 Supabase 쿼리 구조 변경
- 기준치수·공차 저장 형식 변경

## 설계

### UI와 반응형

- 모바일: 기준치수 셀의 입력 너비를 유지하고 목록은 화면의 사용 가능한 너비 안에서 표시한다.
- 태블릿: 테이블 가로 스크롤과 독립적으로 목록을 Portal에 표시한다.
- 데스크톱: 입력란 너비를 최소 너비로 삼고 구간·공차 정보를 한 행에 표시한다.
- 로딩/빈 상태/오류/권한: 로딩 중 안내, 일치 결과 없음, 기존 조회 오류 문구를 각각 표시한다.
- 접근성: 행별 명확한 aria-label, 키보드 탐색, 강조 후보와 선택 동작을 제공한다.

### Server/Client 경계

- Server Component/Action: 기존 `getInspectionToleranceRanges`를 그대로 사용하며 입력할 때마다 서버를 재조회하지 않는다.
- Client Component/Zustand: 품목 선택 시 받은 범위를 행별 자동완성에서 클라이언트 필터링한다. 지역 상태만 사용한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 변경 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: migration 없음. UI 컴포넌트 변경을 되돌리면 된다.

## 변경 계획

1. 오차범위 후보의 검색·표시·선택을 담당하는 route-local 자동완성 컴포넌트를 추가한다.
2. 검사항목의 기준치수 input을 자동완성 컴포넌트로 교체하고 기존 행 상태 및 자동 공차 적용 로직과 연결한다.
3. 등록·수정, 직접 공차 수정, 품목 변경 시 상태 전환을 확인한다.

## 위험과 승인 사항

- 이번 요청은 성적서 관리의 `기준치수` 입력란에 오차범위 검색 결과를 표시하는 것으로 해석했다. 오차범위 관리 화면 자체에 별도 검색 조건을 추가하는 요청이라면 범위를 다시 정해야 한다.
- 후보를 명시적으로 선택하면 해당 행에 사용자가 직접 입력해 둔 공차가 있더라도 선택한 오차범위 값으로 교체한다.
- DB 변경은 없다.
