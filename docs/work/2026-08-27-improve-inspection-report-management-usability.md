## 배경과 목적

현재 성적서 관리 화면은 마스터 목록의 가로 스크롤, 상세 정보의 긴 세로 배치, 등록·수정 Dialog의 단일 긴 폼 때문에 조회와 입력 모두 한눈에 파악하기 어렵다. 목록 선택, 상세 조회, 등록·수정의 목적을 분리하고 각 영역의 스크롤을 제한해 가독성과 작업 속도를 높인다.

## 범위

### 포함

- 성적서 마스터 목록을 좁은 패널에서도 읽기 쉬운 요약 목록으로 변경
- 우측 상세 정보를 요약 정보, 이미지, 검사항목으로 재배치
- 수정·삭제 동작을 선택한 성적서 정보 영역 가까이 배치
- 등록·수정 Dialog를 고정 높이 구조와 `기본정보`, `검사항목·순번` 단계로 분리
- Dialog 하단 저장/취소 버튼 고정
- 검사항목 표의 헤더 고정과 내부 스크롤
- 작업영역 container 기준 단일/2분할 반응형 개선

### 제외

- DB schema, 저장 규칙, Server Action 변경
- 성적서 필드 추가·삭제
- 측정결과 입력 화면 변경
- 검색·페이지네이션 신규 도입

## 설계

### UI와 반응형

- 모바일/좁은 분할: 마스터 목록과 상세를 세로 배치한다. 목록은 번호·품목코드·기종/품명·고객·상태를 2~3줄 요약 카드로 표시한다.
- 태블릿: 좌측 약 280px 요약 목록, 우측 상세 구조로 전환한다. 상세의 이미지와 검사항목은 폭에 따라 세로 배치한다.
- 데스크톱: 좌측 300~320px 목록, 우측 상세. 상세 상단에 기본정보를 조밀한 key-value grid로 배치하고 하단 이미지/검사항목을 2열로 표시한다.
- 등록·수정: viewport 안에 들어오는 고정 높이 Dialog를 `header / 단계 탭 / body / footer`로 구성한다. body만 스크롤하며 footer는 고정한다.
- 기본정보 단계: 입력 필드를 2~3열로 묶고 품목 선택과 읽기 전용 품목정보를 시각적으로 구분한다.
- 검사항목·순번 단계: 이미지와 검사항목 표를 나란히 배치하고 표 본문만 스크롤한다. 항목 추가와 순번 위치 설정은 표 상단에 둔다.
- 로딩/빈 상태/오류/권한: 기존 동작을 유지하되 빈 상태를 각 패널 안에서 짧게 안내한다.
- 접근성: 요약 목록은 button 역할과 `aria-pressed`를 유지하고 단계 탭은 `role=tablist/tab/tabpanel`, 키보드 이동과 focus 표시를 제공한다.

### Server/Client 경계

- Server Component/Action: 기존 데이터 조회 및 저장 Action을 그대로 사용한다.
- Client Component/Zustand: 선택 성적서, Dialog 단계와 입력값을 기존 지역 상태에 둔다. Zustand 변경 없음.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 해당 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 변경 없음
- migration과 rollback: migration 없음. UI 컴포넌트 변경만 되돌리면 된다.
