## 배경과 목적

결과입력 화면 하단의 고정 작업영역이 검사성적서의 세로 공간을 차지하고, `입력한 측정결과를 저장해요.` 안내와 여러 버튼이 항상 노출돼 화면이 복잡하다. 하단 작업영역을 제거하고 검사성적서 우측 하단에 단일 `+` 플로팅 버튼을 두며, 사용자가 필요할 때만 관련 작업을 펼쳐 사용하도록 한다.

## 범위

### 포함

- 결과입력 하단 고정 버튼·안내 영역 제거
- 검사성적서 표시 영역 우측 하단에 `+` 플로팅 버튼 배치
- 호버, focus 또는 클릭 시 작업 메뉴를 위쪽으로 펼침
- 플로팅 메뉴에 `최근 이력`, `초기화`, `인쇄`, `측정결과 저장` 제공
- `초기화`는 현재 성적서의 측정값 X1~X10과 비고만 비움
- 값이 입력된 상태의 초기화는 확인 Dialog를 거쳐 실행
- 저장 성공·오류 메시지는 고정 영역 대신 플로팅 메뉴 주변의 compact 상태 메시지로 표시
- 인쇄 시 플로팅 버튼과 상태 메시지 숨김

### 제외

- 제품구분과 검사성적서 기본정보 초기화
- 최근 이력 Dialog 및 저장 로직 변경
- 측정이력의 성적서 보기 Dialog 작업 방식 변경
- DB 스키마, 데이터와 RLS 변경

## 설계

### UI와 반응형

- 모바일: 48px 원형 `+` 버튼을 우측 하단에 두고 클릭으로 메뉴를 연다. 메뉴 항목은 아이콘과 텍스트가 있는 48px 버튼으로 위쪽에 쌓는다.
- 태블릿: hover와 focus 시 메뉴를 펼치며 버튼 사이 간격을 유지한다.
- 데스크톱: 성적서 표시 viewport의 우측 하단에 고정해 내부 스크롤 중에도 접근 가능하게 한다.
- 로딩/빈 상태/오류/권한: 성적서가 없으면 메뉴를 표시하지 않는다. 저장 pending 동안 초기화·최근 이력·저장을 비활성화하고 상태 메시지를 compact bubble로 표시한다.
- 접근성: `+` 버튼에 `aria-label`, `aria-expanded`, `aria-controls`를 제공하고 Tab 이동, Escape/바깥 focus 시 닫기와 메뉴 항목의 명확한 이름을 지원한다.

### Server/Client 경계

- Server Component/Action: 기존 저장 action을 변경하지 않는다.
- Client Component/Zustand: 메뉴 열림과 초기화 확인은 결과입력 컴포넌트 지역 상태로 관리한다.

### 데이터와 Supabase

- schema 변경: 없음
- PK/FK/index: 해당 없음
- RLS 정책: 변경 없음
- Storage bucket/path/policy: 해당 없음
- migration과 rollback: migration 없음. 플로팅 메뉴를 제거하고 기존 하단 작업영역을 복구하면 rollback 가능하다.

## 변경 계획

1. 결과입력 form과 성적서 viewport를 기준으로 플로팅 메뉴 위치를 잡는다.
2. `+` 트리거와 최근 이력·초기화·인쇄·저장 메뉴를 추가한다.
3. 초기화 확인 Dialog와 측정값·비고 초기화 함수를 추가한다.
4. 기존 하단 고정 영역을 제거하고 저장 상태 메시지를 compact 형태로 이전한다.
5. hover·click·키보드, 전체화면·분할화면과 인쇄 숨김을 검증한다.

## 위험과 승인 사항

- 초기화는 화면의 미저장 측정값과 비고만 지우며 저장된 현재값이나 과거 이력을 삭제하지 않는다.
- `+` 메뉴가 닫힌 상태에서도 저장 단축키는 기존대로 동작한다.
- 측정이력에서 성적서를 조회하는 읽기 전용 Dialog는 기존 인쇄 버튼 표시를 유지한다.
- DB 변경은 없다.
