## 배경과 목적

검사항목 공차가 숫자 컬럼과 숫자 검증으로 제한되어 `나사`, `육안`, `HRC` 같은 문자 기준을 저장할 수 없다. 공차 원문을 그대로 저장하고 과거 측정이력과 인쇄에서도 동일하게 보존한다.

## 범위

### 포함

- 현재 검사항목과 측정이력 항목의 공차 컬럼을 text로 변경
- 기존 숫자 공차를 문자열로 보존
- 공차 빈칸·숫자·문자 입력 허용 및 100자 길이 제한
- 두 공차가 모두 숫자인 경우에만 하한·상한 순서 검증
- 저장, 이력 호환성 비교, 화면 타입 보완

### 제외

- 측정결과 숫자 컬럼 변경
- 오차범위 테이블 구조 변경
- RLS 및 권한 정책 변경

## 완료 조건

- [x] 기존 숫자 공차 데이터가 유지된다.

## 현재 구현 조사

- 관련 route/component: 검사성적서 관리, 측정결과 입력
- 관련 Supabase table: `inspection_report_items`, `inspection_measurement_run_items`
- 관련 RPC: `save_inspection_measurement_entry`, `save_inspection_measurement_run`
- 문서와 구현의 차이: 공차가 `numeric(14,4)`이고 앱과 RPC도 숫자로 강제한다.

## 설계

### UI와 반응형

- 기존 배치와 반응형은 유지한다.
- 공차 입력의 모바일 키보드 힌트만 일반 텍스트 입력에 맞게 조정한다.

### Server/Client 경계

- Server Action에서 길이와 숫자형 공차 순서를 검증한다.
- Client Component는 공차 원문 문자열을 유지한다.

### 데이터와 Supabase

- 두 테이블의 `tolerance_min`, `tolerance_max`를 nullable `text`로 변경한다.
- 최대 100자, 빈 문자열 금지 check constraint를 적용한다.
- 기존 PK/FK/index와 RLS는 유지한다.
- rollback은 문자 데이터 제거 또는 숫자 변환 후에만 가능하다.

## 결과

- 변경: 현재 검사항목과 이력 스냅샷의 공차 컬럼을 text로 전환하고, 저장·비교·입력 UI가 문자 원문을 유지하도록 수정했다.
- 검증: `npm run lint`, `npx tsc --noEmit` 통과. 원격 migration 적용 후 dry run에서 `upToDate: true`를 확인했다.
- 미실행: 로그인된 브라우저에서 문자 공차를 실제 입력해 저장하는 수동 시나리오는 실행하지 않았다.
- 남은 위험/후속 작업: 문자 공차가 저장된 뒤 numeric 타입으로 롤백하려면 해당 값을 먼저 숫자로 정리해야 한다.
